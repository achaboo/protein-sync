# Protein Sync
## 一日のたんぱく質 設計ツール

体重と**運動量**から一日の目標たんぱく質を決め、その日の**献立・時間帯別の配分・食費**、
そして不足分を補う**プロテイン（いまは Bpro）**の杯数までを
まとめて設計するブラウザツールです。目標を上回る日は、どの品目を減らすとよいかも提案します。

（リポジトリ名・公開URLは `protein-sync` のままです）

`index.html` 1ファイルで完結します。サーバーも通信も不要で、ダブルクリックするだけで動作します。

---

## 公開URL

**https://achaboo.github.io/protein-sync/**

ブラウザで上記を開くとそのまま使えます。iPhone の Safari では、共有ボタンから
「ホーム画面に追加」しておくとアプリのように起動できます。

## 使い方

1. 上記URLを開くか、`index.html` をダブルクリックしてブラウザで開きます。
2. **① 基本設定** … 体重・食事回数・基本係数を確認します。
3. **② 今日の運動・食事の時刻** … その日に実際にやった運動を入れます。
   有酸素はウォーキング／サイクリングの距離を直接入れます。
   筋トレはその日にやった種目だけチェックを残します。
   食事の時刻もここです（初期値は**朝食7:00のみ。昼食・夕食は空欄＝自動**）。**朝食の時刻が⑤の起点**です。
4. **③ 今日の食事** … 食べたもの（食べる予定のもの）の数量を入力します。
   **②の運動を入れてから来ると、その日の必要量に合わせた数量が入っています。**
5. **「計算する」** を押すと結果が表示されます。
   ③の下には**1週間の型の栄養（各日と週平均、各日の合否）**も出ます。
6. 一度計算したあとは、**①〜③のどこを変更してもその場で自動再計算**されます。
   ボタンを押し直す必要はありません。更新されると結果が一瞬ハイライトされ、
   「④ 計算結果」の右上に最終更新時刻が表示されます。

### 画面の構成

- **タイトル行は画面上部に固定**されます。表示内容はスクロールしても変わりません。
- **①〜⑥は開閉式（アコーディオン）**です。見出しを押すとそのセクションだけが開き、
  **他は自動的に閉じます**。開いているセクションの見出しをもう一度押すと全部閉じ、
  **「① 基本設定」がタイトル行の下に来る位置まで戻ります**
  （畳んだ拍子に途中のセクションが画面上部に残らないようにするため）。
  「計算する」を押すと「④ 計算結果」が自動で開きます。
- 閉じているセクションの入力値もそのまま保持され、計算にも反映されます
  （表示を隠しているだけで、値は消えません）。
- 最後に開いていたセクションを記憶し、次回も同じ場所を開いた状態で始まります。
- **一度「計算する」を押していれば、次に開いたときも④〜⑥を表示したまま**始まります
  （`calculated` を保存内容に持たせています）。iOSはスリープ中にタブを破棄することがあり、
  戻るとページが読み込み直されるため、これがないと結果が消えたように見えます。
  復元のときはハイライト（flash）を出しません（`render({restore:true})`）。
  「入力をリセット」は保存内容ごと消すので、次回は計算前の状態に戻ります。

入力内容はブラウザに自動保存され、次回開いたときに復元されます。
**保存後に追加した食品**（保存データに存在しない品目）は、0のままにせずその日の型の数量を入れます。
ただし **「③ 今日の食事」はその日限りの入力**として扱われ、**日付が変わると 0 に戻ります**
（同じ日のうちに開き直した場合は入力し直さずに済むよう復元されます）。
体重・基本係数・筋トレの重量などは日付に関係なく保持されます。

- **「食事をリセット」**（③の見出し内）… 設定はそのままで、食事の入力だけを初期状態（その日の曜日の型）に戻します。
- **「入力をリセット」** … 確認ダイアログのあと、すべての入力が初期状態に戻り、保存内容も削除されます。

## 入力項目

### ① 基本設定

| 項目 | 初期値 | 説明 |
|---|---|---|
| **体重の7日平均** | 72.5 kg | 目標たんぱく質の算出基準。**その日の値ではなく7日平均**を入れる（v.160でラベルを変更）。更新は毎日でも週1回でもよい |
| 身長 | 177.4 cm | 基礎代謝（Mifflin-St Jeor式）の算出に使う |
| 年齢 | 55 | 同上 |
| 1日の食事回数 | **3食** | 「2食（昼食を抜く）」「2食（朝食を抜く）」も選べる |
| 基本係数 | **1.65 g/kg** | 目標＝体重×この値。**運動しても加算しません**（運動量はエネルギー側へ）。画面のラベルは「たんぱく質 g/kg・運動量にかかわらず同じ」 |
| 必要エネルギーの補正 | **0 kcal** | 推定が実測と合わないときに足し引きする（±600）。ご飯の自動計算にも効く。欄の下の増減ボタンでも入れられる（iPhoneはマイナスが打てないため）。**増量の余剰は `ACTIVITY` に入っている**ので、ここは0のままで構いません |
| プロテインで賄う上限 | 40 % | 目標のこの割合までを粉で補い、残りは食事に回す |
| 運動しなかった日もプロテインを摂る | オフ | オンにすると休養日も不足分をプロテインで補う（回復期向け） |
| プロテインの杯数を指定 | **空欄（自動）** | 不足量から自動で決める。数を入れるとその杯数で固定できる（1〜6） |
| プロテインを1日2回まで摂る | **オン** | 1回（最大3杯）で埋まらない不足を夕方の2回目に回す。標準日は**3杯＝1回で収まる**ので、この設定の有無で結果は変わりません（不足が31.2gを超える日だけ効きます） |
| 朝食の時刻（②） | 7:00 | **1日の起点**。⑤の実時刻はここから組み立てる |
| 昼食の時刻（②） | **空欄** | 空欄なので朝食の3時間後（朝食7:00なら10:00） |
| 夕食の時刻（②） | **空欄** | 空欄なので昼食の4時間後（朝食7:00なら14:00）。2食の型では朝食の8時間後 |

#### 体重は「7日平均」を入れます（v.160）

**ラベルを「体重 (kg)」から「体重の7日平均 (kg)」に変えました。**
欄の下にも理由を出しています（体重計には毎日乗ってよいが、
**1日の上下1〜2kgは水分とその日食べた量**で脂肪の増減ではないこと、
日付が変わっても保持されること）。

その日の値を入れると、目標が毎朝揺れます。

| | 体重1kgあたり | 実測（73.0kg → 76.0kg） |
|---|---|---|
| 目標たんぱく質 | ±1.65 g | 120.5 g → 125.4 g |
| 必要エネルギー | ±16.3 kcal | 2,771 → 2,820 kcal |
| 1食の目安帯 | ±0.3〜0.6 g | — |

**大きさ自体は小さい**（エネルギーの帯は±200kcal）のですが、**揺れの向きが逆**です。
指示どおり食べた翌朝は重いので「もっと食べろ」、食べきれなかった翌朝は軽いので「減らせ」と出ます。
**守るべき数字が毎朝動くこと自体が、続けにくさになります。**

基本係数の目安（画面にも表として表示されます）:

| 入力値 | どんな人・どんな時期に選ぶか |
|---|---|
| 1.2 | 運動習慣がほぼない時期。医師からたんぱく質制限を受けている場合 |
| 1.4 | 体重・筋肉量の維持が目的。食事量が多くない人はここから |
| 1.5 | 週数回の筋トレを続けながら筋肉量を維持〜微増させたい標準的な設定 |
| **1.65**（初期値） | 筋肥大を狙う標準。72.5kgで119.6g |
| 1.8 | **減量中**で筋肉を落としたくない時期。減量期は1.65のままでは足りません（目安 1.8〜2.4 g/kg） |
| 2.0 | 減量幅が大きい時期。この型では実測145.1g・食塩7.0g・飽和14.4gで、どちらの線にも収まります |

**「2食の日は6杯に固定」という規則は2食のときにしか働きません。**3食の日は不足量から自動で決まります。
**いまの型では、この設定を切り替えても結果は変わりません**（実測：オン・オフとも 3杯・合計118.6g）。
標準日の不足が31.2g以下で1回に収まるためです。
初期値をオンにしてあるのは、**不足が31.2gを超える日**（食事を減らした日や基本係数を上げた日）に
2回目へ回せるようにするためです。オフのままだと、その日は3杯で頭打ちになり、
不足を食事側の候補（無脂肪ヨーグルト・納豆など）が埋めることになって食塩と飽和脂肪酸が上がります。

なお**2食の日にプロテインを6杯へ固定する規則も、「プロテインを1日2回まで摂る」がオフなら3杯で止まります**。
①に書いてある上限（1回3杯 × 1日の回数）を超えないようにするためです。

**朝食・昼食・夕食の時刻**はそれぞれ指定できます（②）。**朝食の時刻が1日の起点**で、
昼食・夕食を空欄にすると基本の間隔（昼食＝朝食の3時間後、夕食＝昼食の4時間後）で自動計算します。
指定した時刻は**そのまま使います**。3時間空かない場合も指定を優先し、実際の間隔を
「○時間後」に出すので、詰まっていることが分かります。
**昼食と夕食には「自動計算にする」ボタン**があり、押すと空欄に戻って基本の間隔で並びます。
朝食は1日の起点なので、このボタンはありません（空欄にもできますが、その場合は
後ろの食事からさかのぼった時刻が入ります）。

**プロテインは水で溶かします。**乳類は使わないため、液体からのたんぱく質の加算はありません。

**①の2つの設定は別の軸です**（v.151で文言を直しました）。

| 設定 | 決めるもの | 初期値 |
|---|---|---|
| プロテインを1日2回まで摂る | **回数**。オンなら1回で埋まらない不足を夕方の2回目に回す | オン |
| 運動しなかった日もプロテインを摂る | **休養日に摂るかどうか**。オフなら休養日は0杯 | オフ |

機能は直交していて、4通り×運動あり／なしの8通りすべてで正しく動きます。
ただし**文言が噛み合っていませんでした**。①の説明が回数だけを見て
「運動直後と夕方の2回まで摂ります」と言い切っていたため、すぐ後ろの
「運動しなかった日は起床後に…」と矛盾していました。いまは両方の設定を見て、
「運動した日は…」「運動しなかった日は…」と分けて書きます。

**粉を1杯も摂らない日は、⑤にプロテインの行を出しません**（v.151）。
運動もしておらず「休養日も摂る」もオフの日に、
「起床後（朝食前）／—／—」という中身の無い行が残っていました。

**水の量は杯数ごとの表示には出していません**（v.143）。計算に一切使わない値で、
商品の表示も「水240ml**程度**」だからです。しかも1回分（2杯）に対する量なので、
運動直後の3杯や2回目の1杯にそのまま添えると数字のほうが合いません。
①に商品の表示として1回だけ載せ、あとは「水で溶かす」とだけ書いています。

**運動していない日はプロテインを摂りません**（目標分はすべて食事から確保します）。

**「プロテインの杯数を指定」**に数を入れると、自動計算を上書きしてその杯数で組み立てます。
入れられるのは **1〜「1回3杯 × その日に許した回数」**（「プロテインを1日2回まで摂る」がオンなら**6杯**、
オフなら3杯）です。3杯を超える指定は自動で**回数に分けます**。
分け方は**1回目から先に満たす**ので、4杯なら 3杯＋1杯です
（後ろの回には最低 `MIN_PER_SERVE` 杯を残します）。
上限を超える数を入れたときは、入力欄の下に
「7杯は指定できません。いまの設定では最大 6杯 です（1回3杯まで×1日2回）。」と出ます。

④には「杯数を手動で5杯に指定しています（自動計算では4杯）」と併記されるので、
自動計算の値は見失いません。空欄に戻せば自動計算に戻ります。

**毎日同じ杯数で飲みたい場合はここに入れてください。**自動計算は不足量に合わせて動くので、
食事が多い日は杯数が減ります（6杯＝62.4gより不足が小さければ、その分だけ杯数が下がります）。
固定すると不足量にかかわらずその杯数になるため、食事が足りている日は目標を上回ることがあります。

**「プロテインを1日2回まで摂る」をオンにすると**、1回（最大3杯・31.2g）で埋まらない不足に対して
**夕方の2回目**を割り当てます。⑤には「2回目のプロテイン」の行が出て、時刻は夕食から
さらに3時間後です。夕食を食べきれず、その分を粉に回したいときに使ってください。

なお「運動直後30分以内でなければ効果がない」というのは古い理解です。運動後に筋タンパク合成の
感受性が高まる状態は**数時間〜24時間程度続きます**。効果への寄与は
**①1日の総量 ＞ ②1回あたりの量と分散 ＞ ③タイミング** の順で、特に加齢に伴う同化抵抗性を考えると、
1回にまとめるより**確実に入る量を複数回に分ける**ほうが有利です。

**プロテインの1回目には時刻を出しません。**日に何回か運動する日があるので、「運動を終える時刻」を
1つに決められないためです。⑤の1行目は「**運動のあとのプロテイン（1回目）**」とだけ表示し、
その日の運動のうち**どれか1回のあと**に摂ってもらう形にしています。

順番を気にする必要もありません。運動後に感受性が高まる状態は数時間〜24時間続くので、
朝食の前でも後でも効果は変わりません。バナナは1回目と同じ行に出ます。

**2回目のプロテインだけは時刻が出ます**（夕食の3時間後）。こちらは食事を起点に決まるためです。

**「運動しなかった日もプロテインを摂る」をオンにすると**、休養日も**不足があるときだけ**
起床後に1回摂る計算になります。筋トレをした日と違って最低杯数の縛りはないので、
食事だけで目標に届いていれば0杯です。オーバートレーニングからの回復期など、
運動量を落としてもたんぱく質は落としたくない時期に使ってください。

### ② 今日の運動・食事の時刻

**運動は曜日で固定していません。**その日に実際にやった内容を入れると、
それだけが必要エネルギーに乗ります。**「8種目×3セット」を毎日の標準とはしていません。**

#### 入力したかどうかを区別します

運動の入力欄の値は前回のまま残るので、放っておくと
**「運動していない日」と「まだ入力していない日」の区別が付きません**。
そこで最後に確定した日付（`exDate`）を持ち、今日でなければ②の先頭に出します。

> ⚠ 今日の運動はまだ入力していません。下の内容は前回入力したときのままです。
> **今日の内容に直してください**（運動しなかった日は距離を0にし、全種目のチェックを外します）。
> 有酸素の距離か筋トレの欄を触るか、**「計算する」を押す**と入力済みになります。
> ④の必要エネルギーは、いまは下の内容で**仮に**計算しています。

入力済みの日は「**今日の運動を入力済みです。**（3種目 / 総負荷量 2,475kg / 有酸素なし）」のように出ます。
距離0・全種目チェックなしで入力済みになった日は
「**今日の運動を入力済みです。運動なし（休養日）**として計算しています。」です。

入力済みに変わるきっかけは2つです。

| きっかけ | 備考 |
|---|---|
| **有酸素の距離か筋トレの欄を触る** | 同じ②にある食事の時刻を触っただけでは変わりません |
| **「計算する」を押す** | 画面を見て自分で押したときだけ。入力の変更による自動再計算では変わりません |

未入力のあいだは、④のエネルギー行にも
「⚠ ②の運動は今日の分が未入力です。前回の内容で仮に計算しています。」と出ます。

**入力は毎日この欄に手で入れる前提です。**「今日はこの内容で確定」「今日は運動していない」の
2つのボタンは v.122 で削除しました。毎日手入力するなら、欄を触った時点で入力済みになるため
不要だからです。

ただし**前回とまったく同じ内容の日（連続した休養日や、同じメニューを続けた日）は
どの欄も触らない**ので、欄を触る側の判定では⚠が消えません。
そのために **v.123 で「計算する」も確定のきっかけに加えました**。
このため、②を見直さずに「計算する」を押した日は、**前回の運動の内容がそのまま
今日の分として確定します**。⚠が出るのはその日まだ一度も計算していないあいだだけなので、
②の内容は計算する前に確かめてください。

#### 有酸素

ウォーキング（km）／サイクリング（km）を**その日の実績で直接入れます**。
やらなかった種目は 0 のままにします。距離のプリセットボタン（`CARDIO_PRESETS`）は
v.122 で削除しました（距離が日によって違うため、ボタンでは入らない）。

#### 筋トレ

8種目それぞれに **チェック・重量・回数・セット数** があり、
**チェックの入っている種目のセット数だけ**が総負荷量（＝消費エネルギー）に入ります。
その日にやった種目だけチェックを残してください。

部位分けのプリセット（`EX_PRESETS`。全種目／背中・腕／胸・肩／胸・腕・肩（後）／なし）は
v.122 で削除しました。組み合わせが日によって違うので、種目ごとのチェックで作ります。

入力欄の下に「**本日の入力：3種目 / 合計 9セット ／ 総負荷量 2,475 kg**」と出ます。

| 種目 | 部位 | 初期値 |
|---|---|---|
| ラットプルダウン | 背中 | 25 kg / 15回 / 3セット |
| シーテッドローイング | 背中 | 20 kg / 15回 / 3セット |
| チェストプレス | 胸 | 20 kg / 15回 / **6セット** |
| ショルダープレス | 肩 | 10 kg / 15回 / 3セット |
| ディップス | 胸 | 35 kg / 15回 / 3セット |
| バイセップスカール | 腕 | 10 kg / 15回 / 3セット |
| サイドレイズ | 肩 | **8.5 kg** / 10回 / 3セット |
| リアレイズ | 肩 | **8.5 kg** / 5回 / 3セット |

重量は **RIR（Reps In Reserve）1〜2** ＝ 各セット終了時に「あと1〜2回できる」程度を基準に設定します
（この目安は画面上の筋トレ見出しの下にも表示されます）。
重量欄は `step="any"` なので、8.5kg のような小数も入れられます。

**初期状態ではどの種目にもチェックが入っていません**（v.128 から）。
その日に実際にやった種目だけチェックを入れてください。
チェックが1つも無く有酸素も0の日は**休養日**として扱われ、プロテインは0杯になります
（①で「運動しなかった日もプロテインを摂る」をオンにしない限り）。
参考までに、8種目を初期値どおり（合計27セット）行うと総負荷量は **6,682.5 kg** です
（v.141でサイドレイズ・リアレイズを 5.75 → 8.5kg、チェストプレスを 3 → 6セットにしました）。

#### そのほか

- **食事の時刻**: 朝食（初期値 7:00）・昼食（**空欄**）・夕食（**空欄**）。
  空欄の食事は基本の間隔で並びます。朝食7:00なら**昼食10:00・夕食14:00**
  （2食の型では夕食は朝食の8時間後）。違う時刻にしたい日は欄に直接入れてください。
  **朝食の時刻が1日の起点**で、⑤の実時刻はここから組み立てます。
  牛丼チェーンの**朝食メニューは11:00まで**しか注文できません。
  外食の朝食を食べる日に朝食の時刻が11:00を過ぎると、⑤の朝食行に警告が出ます。
- **運動の時刻は入力しません。**日に何回か運動する日があるため、1つの時刻に決められないからです。
  プロテインの1回目は「運動のあと」とだけ表示し、時刻は出しません。

入力欄の初期値を変更した場合は `DEFAULTS_VER` を上げ、対象の入力欄を `RESET_IDS` に含めてください。
`<select>` には `defaultValue` が無いため、初期値へ戻すときは `defaultSelected` の付いた
選択肢を探して代入します（`el.value = el.defaultValue` だと値が空になります）。
保存済みの値を復元せず新しい初期値を使うようになります
（体重・食事回数・プロテインの上限など、対象外の設定は保持されます）。

`RESET_IDS` には**そのとき実際に変えた欄だけ**を残してください。前回の分を残したままにすると、
次の更新のときに利用者が入力済みの値（体重など）まで初期値へ戻ってしまいます。
v14（体重 73.5 → 72.5／プロテインの杯数の指定 8杯 → 空欄／昼食・夕食の時刻 → 空欄）では
`['weight','fixSpoons','lunchTime','dinnerTime']` を対象にしていました。
**v15（サイドレイズ・リアレイズの重量 5.75 → 8.5kg／チェストプレスのセット数 3 → 6）では
`['w_side','w_rear','s_chest']` だけ**にしてあります。v14の4つを残すと、
入力済みの体重や時刻まで初期値へ戻ってしまいます。
**筋トレのチェックだけは `RESET_IDS` では扱えません**（`<input type="checkbox">` で
`defaultValue` を持たないため）。`load()` の `staleEx` で、版が違えば保存内容を復元せず
新しい初期値（全部オフ）を使う形にしてあります。`twoDoses` と同じ扱いです。

### ③ 今日の食事

#### 品目ごとの「今日は使う／使わない」（v.150）

**各品目の名前の左にチェックがあります。初期値は全部オン**で、そのときはこれまでどおりの
自動計算です。**在庫が無い日や気が進まない日は外してください。**

- 外した品目は**数量を0として扱い**、自動計算の組み立てからも外します
  （探索の変数から消えるので、その品目を使わない前提で最良の組み合わせを探し直します）
- **固定メニューも外せます。**まぜのっけ朝食を外すと、その17.1gを候補やプロテインが埋め直します
- ④の「エネルギーが足りないときの追加候補」や早見表にも出しません
  （使わないと決めた品目を勧めるのは食い違うため）
- **「その他（自由入力）」から足した品目にも付きます**（初期値オン）
- 外している品目があるときは、③の先頭に「○品目を今日は使わない設定にしています（…）」と出ます
- **その日限りの設定**です。翌日と「食事をリセット」で全部オンに戻ります
  （食事の数量と同じ扱い。当日の設定リンクからは運べます）
- **店のメニューはチェックを品目名の左に置きます**（店名は見出しなので、
  そこに付けると店ごと外すように見えるため）

**「1週間の型の栄養」の表はこの設定を見ません。**あちらは今日の在庫とは無関係の基準なので、
外した品目があっても型どおりの数字を出します。

#### 曜日ごとの型

**朝食は外食チェーンの固定メニュー、夕食は週6日が自宅（サバ缶）**です（1食＝1単位）。

自宅の食材（サバ缶・ご飯・納豆・卵・トマトジュース・サラダ一式）は外食に持ち込めないので、

**ご飯・オリーブオイル・たんぱく質の候補（ヨーグルト／納豆／ツナ缶／サラダチキン）は、

#### 「価格・栄養成分を変更」

各品目の行に付いているボタンで、**1単位あたりの値をその場で直せます**。
値上げやリニューアルのたびに `index.html` を書き換えなくて済むようにするためです。

直せるのは **たんぱく質／エネルギー／脂質／飽和脂肪酸／炭水化物／食物繊維／食塩相当量／価格** の8つで、
並びは商品の栄養成分表示に合わせてあります。

- 変えた品目は注記の横に「**変更済み**」と出ます。たんぱく質を変えると「1食 約○g」の表示も追従します
- 初期値と同じ値に戻した項目は保存しません。**変えた分だけ**を `foodOverride` に持ち、
  `FOODS` へ上書きして使います（初期値は `FOOD_BASE` に控えてあります）
- 戻し方は2通り。編集枠の**「この品目を初期値に戻す」**と、
  ③の合計の下に出る**「すべて初期値に戻す」**です
- **日付では消しません**（値段は翌日も同じもののため）。食事の数量とは扱いが違います。
  「食事をリセット」でも消えません。消すのは「入力をリセット」だけです
- **設定リンクにも載ります**。こちらは設定と同じ扱いで、日付が違うリンクからでも反映されます

初期からある品目は、品目名・単位・配分の枠は変えられません（名前ごと変えたいものは、
下の「その他（自由入力）」から品目として足してください）。
**自由入力から足した品目は、ボタンが「品目名・価格・栄養成分を変更」になり、
品目名と単位も直せます**（初期値が無いので「初期値に戻す」は出ません。消すときは隣の「削除」）。

#### 「この内容で品目を追加」

入れた内容を**そのまま③の品目にできます**。ボタンを押すと、入力した値を**1つぶんの量**として
一覧の末尾に他の品目と同じ書式で並びます。

```
サラダチキン
1食 約20.9g 278円          [ 1 ] 食
[削除]
```

**個数は足した行の数量欄で変えられます**（2にすればたんぱく質も価格も2倍になります）。
単位は `#otherUnit` で指定でき、既定は「食」です（ヨーグルトなら「個」など）。
足したあとは入力欄が空に戻るので、続けて次の品目を入れられます。

- 足した品目は **`FOODS` に追加**されるので、④の合計・⑤の配分・合計金額・
  「残りをどうするか」の早見表まで、他の品目とまったく同じに扱われます
- 配分の枠は朝食・昼食・夕食（`slots:['b','l','d']`）で、固定はしません
- **翌日以降も残ります。**品目そのもの（名前・栄養成分・価格）は価格の変更と同じ扱いで、
  日付では消しません。日付で0に戻るのは**数量だけ**です
- 「食事をリセット」でも品目は残り、数量だけ0に戻ります。
  消したいときは行の**「削除」**ボタン（こちらは元に戻せません）
- 足したあとで値を直したいときは、行の**「品目名・価格・栄養成分を変更」**から。
  **品目名と単位も含めて**直せます（初期値が無いので「初期値に戻す」は出ません）
- 品目名の `<` `>` は入力時に落とします。名前は④や⑤など多くの場所へそのまま出るためです
- 保存（`localStorage` の `cf`）と**設定リンク**にも載せます。リンクからは品目を持ち込み、
  数量は当日のリンクのときだけ入ります

品目にせず値だけ入れた場合は、これまでどおり「その他」としてまとめて合計に入ります
（⑤では「その他（○g）」の1行になります）。こちらは**その日限り**で、翌日には消えます。
**繰り返し食べるものは品目にしておくと、翌日以降は数量を入れるだけで済みます。**

栄養成分表示に飽和脂肪酸が載っていない商品のために、**「飽和脂肪酸が書かれていないときは」**の
折りたたみを添えてあります（`SAT_RATIO`）。食品の種類ごとに「脂質のうち飽和脂肪酸が占める割合」を
表にし、種類を選んで押すと**脂質の欄から計算して飽和脂肪酸の欄へ書き込みます**。

**脂質**（`fat`）は各社の公表値です。④では総エネルギーの**20〜30%**を目標範囲として表示し、
あわせて「うち飽和脂肪酸 ○g（○%）」を添えます。炭水化物も同様に**50〜65%**の範囲で判定します。

この割合は**実際に摂ったエネルギーに対して**見ています。必要量を分母にすると、エネルギーが
足りない日はどの栄養素も自動的に「少ない」と出てしまい、量の不足と配分の偏りが区別できなくなるためです。

④の各行には**「多い」「少ない」「ちょうどよい」の札**を付けています。赤いだけでは
多いのか少ないのかが分からないので、色も分けています（多い＝赤／少ない＝橙）。
本文も札に合わせ、判定が「ちょうどよい」の行では「足りません」「超えています」のような
強い言い方をしません。

飽和脂肪酸（`sat`）は各社が公表している総脂質量に、日本食品標準成分表の脂肪酸比率を
当てて算出した推定値です。牛丼・豚丼・卵の多いメニューは総脂質の35〜40%、
親子丼は約29%、大豆（納豆）は約16%、サバは約26%が飽和脂肪酸にあたります。
「その他（自由入力）」はたんぱく質量しか分からないため合計に数えません。

たんぱく質と脂質は各社の公表値です。まぜのっけ朝食・得朝牛皿定食・ハムエッグ納豆定食の3品は、
当初は推定値を入れていましたが、公表値（17.1g／13.5g／24.1g）に差し替えました。

**アーモンドは1粒＝1.0gとして数えます**（v.149）。100gあたりの値を1/100にしたもので、
1粒＝たんぱく質0.209g・6.29kcal・脂質0.541g・3.8円。**1日10粒（10g＝約63kcal）まで**です。
**飽和脂肪酸0.04gと食物繊維0.101gは日本食品標準成分表「アーモンド（乾）」からの推定値**で、
利用者の提示値には含まれていませんでした。飽和脂肪酸は15gの制約に、食物繊維は22g以上の
判定にそれぞれ効くので、0のままにすると脂質54.1g/100gの品目が制約をすり抜けます。
**鉄3.4mg・ビタミンE19.3mg（いずれも100gあたり）はこのツールでは追っていません。**

**「納豆（たれなし）」は食塩を削りたい日の切り替え先です**（v.145）。たれをかけて食べるのが
基本なので、**自動計算の候補には入れていません**。食塩の残り枠が無くて納豆を足せない日に、
手で数量を移してください。食塩0gは日本食品標準成分表の「糸引き納豆」の値です
（たれは別添なので豆の側は0g）。**ほかの値は「納豆」と同じまま**にしてあるので、
炭水化物とエネルギーはたれのぶんだけ多めに出ます（1パックあたり数kcal）。
お使いの商品のラベルと違う場合は、行の**「価格・栄養成分を変更」**から直してください。

**食塩相当量**（`salt`）は外食メニューは各社の公表値、自宅の食材は商品ラベルの値です。
Bproは1回分（30g）0.64g の公表値です（1杯0.32g）。
④に1日の合計を出し、成人男性の目標量 **7.5g未満**（`SALT_LIMIT`）を超えると警告枠を出します。
警告にはその日いちばん減らしやすいものを名指しします（みそ汁を外す／納豆のたれを使わない）。
外食メニューは1食2.3〜3.4gあり、朝夕とも外食の日は店のメニューだけで5g前後になります。

**炭水化物**（`carbG`）も各社の公表値です。FOODS には「糖質が多いメニュー」を示す真偽値の
`carb` が別にあるので、数値のほうは `carbG` という名前にしてあります（同名にすると上書きされます）。

**食物繊維**（`fiber`）は自宅の食材と プロテイン・納豆は商品ラベルの値ですが、
**外食メニューは各社が公表していない**ため、炭水化物からご飯の量を割り出し、具材（納豆・とろろ・
みそ汁など）を足した推定値です。丼もので4g前後、納豆の付く定食で7〜8gとみています。

**エネルギー**（`kcal`）は公表値です。1日の必要量は Mifflin-St Jeor 式の基礎代謝に
`ACTIVITY` **1.63** を掛け、運動による**正味の**消費（安静時代謝を差し引いた分）を足して出します。
1.63は**活動レベル1.50（座位中心）＋ ゆっくり増量の余剰0.13**をまとめた値で、そこへ入力された
運動の正味消費を加えるのはこのツール独自の推定モデルです（詳しくは「4. 運動量に比例するのはエネルギー」）。
この値は**推定値**です（①の「必要エネルギーの補正」で実測に合わせられます）。**入力した品目だけの合計**なので、
リストにないものを食べた日は実際の摂取はもっと多くなります。
過不足が100kcalを超える日は、体脂肪1kg＝7,200kcal として**週あたりの体重変化**も添えます。

#### 自動で数量が決まる品目

**曜日で固定していない14品目は、その日の栄養バランスから自動で決まります**
（ご飯・店の無料ご飯・オリーブオイル・ミックスサラダ・無脂肪ヨーグルト・納豆・
ツナ缶・サラダチキン・卵・バナナ・アーモンド・低脂肪牛乳・全粒パン・シリアル）。栄養素ごとに担当を決めて順番に埋めるのではなく、
**7項目すべてが「ちょうどよい」に入る組み合わせを探します**（`autoQuantities`・v.144）。
詳しくは下の「自動計算は『全部の栄養素を同時に見て』組み合わせを選びます」を参照してください。

いずれも**手で書き換えるとその日は手入力が優先**され、入力欄の下に「手入力に切り替えています」
と出ます。**「自動計算に戻す」ボタン**で戻せます。切り替えはその日限りで、翌日は自動計算に戻ります
（「食事をリセット」でも解除されます）。

#### ご飯のおかわり（吉野家・松屋）

エネルギーが足りない日に**無料で足せる**ため、店のご飯を単品で持っています
（吉野家 ご飯 並盛／松屋 ライス 並盛）。飽和脂肪酸も食塩もほぼ0で、
1杯で343〜344kcal入る、この設計でいちばん効率のよいエネルギー源です。
大盛は食べないため置いていません。

おかわりができるのは**定食を食べたときだけ**なので、目印にする品目を `teishoku` で指定しています。

| 店 | おかわりできる定食 |
|---|---|
| 松屋 | 得朝牛皿定食 |
| 吉野家 | ハムエッグ納豆定食／塩さば得朝定食 |

丼・牛めし（吉野家 豚丼、松屋 牛めし、すき家 牛丼・まぜのっけ朝食、なか卯 親子丼）は対象外です。

**自動入力**します（`autoEnergy`）。**入れられる条件は1つだけ**です。

- **その店の定食を食べる日**であること（同じ `shop` の `teishoku` が1つ以上入っている日）。
  `autoRanges` が上限を「その日 1杯／それ以外の日 0杯」に切り替えます

**0杯にするか1杯にするかは、ほかの13品目とまったく同じ探索が決めます。**
「エネルギーが `ENERGY_CARE` 以上足りない日だけ入れる」という別立ての規則は**ありません**
（v.144 で全栄養素を同時に見る探索に替えたとき、この規則は無くなりました。
README に条件として残っていたのは書き漏らしで、v.157 で直しました）。

置く時間帯は**その定食と同じ枠**です。木曜（吉野家 ハムエッグ納豆定食＝朝食）なら朝食に入ります。

自動で入るのは**1杯まで**です。1杯で足りない日は、下の「エネルギーが足りないときの追加候補」に
「この品目だけで埋めるなら何杯」という形で出ます（無料なので上位に来ます）。

#### 木曜の実測（v.162で測り直し）

1週間の型では、定食が入るのは木曜だけです（ハムエッグ納豆定食＋なか卯 親子丼の日）。
**運動を入力したかどうかで、入る・入らないが入れ替わります。**

| 木曜 | 粉 | 無料ご飯 | 自宅のご飯 | 献立 | 必要量 |
|---|---|---|---|---|---|
| 筋トレ8種目を入力 | 4杯 | **1杯** | 1杯 | 2,746 kcal | 2,763 kcal |
| 運動を入力しない | 0杯 | **0杯** | 2杯 | 2,616 kcal | 2,549 kcal |

**運動した日に入る**のは、粉が41.6gのたんぱく質を賄うぶん、食事側はエネルギーを稼ぐ役に
回れるからです。**無料で343kcal・食塩も飽和脂肪酸もほぼ0**なので、この型でいちばん効率のよい
エネルギー源になります。

**運動しない日に入らない**のは、粉が0杯でたんぱく質を食事側だけで埋める必要があり、
そのために入る候補（ヨーグルト4杯・低脂肪牛乳2杯・シリアル2食・納豆1P）が
エネルギーも一緒に運んでくるためです。

#### エネルギーが足りないときの追加候補

必要量を300kcal以上（`ENERGY_CARE`）下回る日は、栄養成分表の下に
**③の品目から手早く足せるもの**を3つまで挙げます。

並べる基準は「その品目のkcal」ではなく、**足したときに1日の合計が実際に増える量**です。
たんぱく質を含む品目を足すと自動計算の候補がそのぶん減るため、
**正味 ＝ その品目のkcal −（たんぱく質g ÷ 候補のg × 候補のkcal）** で見ます。
基準にするのは、その日いちばん多く入っている候補です（多くの日は無脂肪ヨーグルトになります）。

| 品目 | 表示上のkcal | 正味（納豆が1P入っている日の例） |
|---|---|---|
| トマトジュース | 34 | +13 |
| サバ缶 | 268 | **−110**（納豆が4P近く減るため、かえって下がる） |

**ご飯・バナナ・オリーブオイル・卵は自動計算の対象になった**ので、この表には出ません
（v.144。自動で数量を決めている品目に「さらに足してください」と出すのは食い違うためです）。
そのぶん、ここに出る品目は少なくなりました。

正味20kcal未満の品目は候補にしません。卵やサバ缶のように相殺されるものは、
「足しても合計はほとんど増えません」と理由を添えて名前だけ出します。
候補が0の日は相殺が起きないので、公表値のまま並べます。

各候補には**この品目だけで埋める場合の数量・金額・増える飽和脂肪酸と食塩**を出します。
数量は**飽和脂肪酸15g・食塩7.5gの残り枠を超えない数まで**で、それでも埋まらない場合は
「あと○kcal残ります」と書きます。1単位が大きくて150kcal以上超える場合は、超過量も添えます。

この枠に使う値は、自動計算の**候補**が越えない線（`SAT_GOOD` 15g / `SALT_LIMIT` 7.5g）と同じです。
ここだけ上限の17gまで勧めると、自動計算の方針と食い違うためです。
（ご飯は1杯0.1gと小さく、下の `SAT_PER_UNIT_MIN` 0.4g に届かないので、
もともと飽和脂肪酸の残り枠では絞っていません。ご飯を17gで止めるのと整合しています。）
1単位あたりの量がわずかな品目（ご飯0.1g・バナナ0.1gなど）は枠の計算対象にしていません
（しきい値は `SAT_PER_UNIT_MIN` 0.4g / `SALT_PER_UNIT_MIN` 0.2g）。

店のメニュー（`shop` のある品目）は曜日で決まっているため、候補には出しません。
例外は上のご飯のおかわりで、**その店に行く日だけ**候補に入ります（無料なので上位に来ます）。

**自動で数量を決めている品目（自宅のご飯・オリーブオイル）は、その日の上限までしか勧めません。**
ご飯の上限は `autoMax` 6杯と「1食あたり2杯 × 自宅で食べる食事の数」の小さいほうで、
置ける食事が無い日（朝も夕も外食で昼食も無い日）は候補にも出しません。

上限まで入っている日はその品目を候補から外し、代わりに
**「ご飯 6杯・オリーブオイル 7さじは自動計算の上限まで入っています。
これ以上は③のほかの品目か『その他（自由入力）』で補ってください」**と表示します。
自動で6杯入れておきながら「あと3杯足してください」と出すのは食い違いだからです。

#### 自動計算は「全部の栄養素を同時に見て」組み合わせを選びます（v.144）

**自動で数量が決まるのは次の14品目**です。

| 品目 | 範囲 | 役割 |
|---|---|---|
| 自宅のご飯（0.5合） | 0〜6杯 | エネルギーの主な調整手段 |
| 定食の日の無料ご飯 | 0〜1杯 | その店に行く日だけ |
| オリーブオイル | 0〜7さじ | 脂質（一価不飽和）。サラダの無い日は0 |
| ミックスサラダ | 0〜3皿 | 食物繊維と、油の置き場所 |
| 無脂肪ヨーグルト | 0〜4杯 | たんぱく質（食塩0.1g・飽和0.2gと軽い） |
| 納豆 | 0〜3P | たんぱく質・食物繊維・脂質 |
| ツナ缶 | 0〜2缶 | たんぱく質・脂質（飽和3.8gと重い） |
| サラダチキン | 0〜2P | たんぱく質（食塩2.2gと重い） |
| 卵 | 0〜2個（メニュー分を引いた残り） | たんぱく質・脂質 |
| バナナ | 0〜3本（運動した日は1本以上） | 糖質・エネルギーの細かい調整 |
| アーモンド | 0〜10粒 | 脂質（一価不飽和）・食物繊維・エネルギーの細かい調整 |
| 低脂肪牛乳 | 0〜3杯（600ml） | たんぱく質（食塩0.22gと軽い） |
| 全粒パン | 0〜3枚 | エネルギー・食物繊維。1枚154kcalでご飯より刻みが細かい |
| シリアル | 0〜2食（60g） | 食塩0g・飽和0.5gで食物繊維3.0g。いちばん軽い候補 |

**以前は栄養素ごとに担当を決めて順番に埋めていました**（脂質＝油、エネルギー＝ご飯、
たんぱく質＝候補4つ）。この作りには原理的な弱点がありました。**担当をまたぐ手が
見つからない**のです。実際、油は7さじが上限なので脂質だけでは20%の線に届かず、
④の脂質はほぼ毎日「少ない」のままでした。

総当たりで調べると、**同じ品目の範囲のままで7項目すべてを「ちょうどよい」に
入れる組み合わせが存在していました**（筋トレのみの日で10,080通り中28通り）。
見つけるには「ご飯を1杯減らして総エネルギーを下げ、脂質の目標そのものを下げつつ、
別の品目で脂質を足す」という**同時の判断**が要ります。

そこで自動計算を、**品目の組み合わせをひとつの点として探す**形に変えました。

**選ぶ順番**（上にあるものほど強く効きます）

1. **食塩7.5g・飽和脂肪酸15gを越えない**（候補も油もご飯も。越える組み合わせは選びません）
2. **たんぱく質が目標の99%（`WEEK_P_RATIO`）を下回らない**（週の表の合否は95%ですが、探索はそれより厳しい側を狙います）
3. **エネルギー・脂質・炭水化物・食物繊維が「ちょうどよい」の帯に入る**
   （たんぱく質の上振れもここ。食物繊維は合否に入れていないので軽くしています）
4. **エネルギーが必要量に近い**（帯の中でも近いほうがよい。`ACTIVITY` に増量の余剰が
   入っているので、帯の下端に寄せると余剰が消えてしまいます）
5. **食塩と飽和脂肪酸の余裕が大きい**（LDLを下げる方針を優先します）
6. **食費が安い**

**探し方は山登り法**です。1品目ずつ±1で点数が下がる手を探し、
下がらなくなったら2品目を同時に動かす手（−＋／＋＋／−−）まで見ます。

| 始める点 | 数 | 中身 |
|---|---|---|
| 決まった点 | 7 | 全部0／**いま入力欄に入っている数量**／中央／上限／候補だけ満たす／ご飯だけ満たす／たんぱく質を持つ品目だけ上限 |
| 散らした点 | `CLIMB_SEEDS` 8 | 固定の種から作る乱数（日替わりにしないので、同じ条件なら毎回同じ答え） |
| 揺さぶり直し | `CLIMB_KICKS` 40 | 見つかった最良点の2〜3品目を±2動かして登り直す（反復局所探索） |

たんぱく質の合格線を割る答えしか出せなかったときは、**初期点6倍・揺さぶり3倍**でやり直します。
そこを割ると週の表が✕になるので、そのときだけ時間をかけます。

実測（平日・筋トレ8種目・14品目）で**1回の探索が約280ms**、
①の設定を1つ変えたときの**再計算全体が約350ms**です（週の表は `balCache` から返るため。
2回目以降は6ms）。**v.156 で2倍ほど遅くなりました**（v.155は120ms／150ms）。
品目が11→14になって組み合わせが48倍に増えたためで、体感できる遅さではありません。

**「いま入力欄に入っている数量」を初期点の1つに使っている**ので、
**同じ設定でも、直前に画面に出ていた数量によって別の局所解に落ちることがあります。**
測り直すときは自動計算の品目をいったん0にしてください。

総当たりと同じ答えに届くことを確認したのは **v.144 の時点（当時は約48万通り）**です。
品目が14種になったいまは平日で **約1億2,800万通り**あり、この照合はやり直していません。
**山登りなので理論上の最良が保証されるわけではありません。**

#### 下の3つは v.156 で足しました

外部レビューの「**高エネルギー・低飽和・低食塩・低調理**の候補を増やすとよい」という
指摘（オートミール・全粒パン・低脂肪乳）に対して、利用者が商品を決めて公表値を出したものです。

| 品目 | 商品 | 1単位 |
|---|---|---|
| 低脂肪牛乳 | 西友 みなさまのお墨付き 低脂肪牛乳 1000ml 236円 | 200ml（1杯） |
| 全粒パン | 敷島製パン 麦のめぐみ 全粒粉入り食パン 6枚 279円 | 1枚 |

日本食品標準成分表から脂質に比率を当てた**推定値**です。

- **低脂肪牛乳 1.1g**＝脂質1.7g ×0.67（成分表「加工乳・低脂肪」の 飽和0.67g／脂質1.0g）
- **シリアル 0.5g**＝脂質2.2g ×0.219（成分表「オートミール」の 飽和1.25g／脂質5.7g）

**公表されている微量栄養素は追っていません**（牛乳のカルシウム240mg、シリアルの
カルシウム15mg・鉄1.3mg・ビタミンB群・水溶性食物繊維1.3g・β-グルカン0.9g）。
このツールは外食メニューの公表値が無いため、そもそも微量栄養素を合計していないためです。
食物繊維だけは総量（シリアル3.0g・全粒パン4.1g）を数えています。

**実際に選ばれるのは、運動した日は シリアル・無脂肪ヨーグルト、
休養日は そこに 低脂肪牛乳・納豆が加わる**という形です。
**シリアルは食塩0g・飽和0.5gで食物繊維3.0g**と軽いので、ほぼ毎日入ります。

**以前は納豆1種類だけを増やしていました。**それだとたんぱく質だけを合わせて食塩・飽和脂肪酸・
食費が置き去りになり、当時のSAVASを正しい値（4杯＝19.5g）に直した途端に納豆が5〜6パック・
食塩12.6gという献立が出てしまいました。納豆はたんぱく質の調整用の変数ではなく、
食物繊維も大豆由来成分もタレの食塩もある1つの食品なので、この作りをやめています。

**自動で数量が決まるのは、上の「14品目」の表にあるものだけ**です
（ヨーグルト・納豆・ツナ缶・サラダチキン・低脂肪牛乳・全粒パン・シリアル・
ご飯（自宅・店）・オリーブオイル・ミックスサラダ・卵・バナナ・アーモンド）。
**ミックスサラダ・卵・バナナは v.144 で、アーモンドは v.149 で、
低脂肪牛乳・全粒パン・シリアルは v.156 で自動計算に入りました。**
残り（外食メニュー・サバ缶・ノンオイルドレッシング・トマトジュース）だけが、
その日の型または `autoDaily` で入る固定分です。どの品目も手で書き換えれば手入力が優先されます。

トマトジュースは**食塩無添加**のものを前提にしています（例：Juver TOMATE 1L・スペイン産、
100mlあたり たんぱく質0.9g／食塩相当量0.03g）。カリウムを足してナトリウムとの比率を整える目的です。

**1日2杯（400ml）**にしているのは、1杯では目標量に届かないためです。この献立のカリウムは
1杯で約2,600mg（目安量2,500mgは満たすが、生活習慣病予防の目標量3,000mgに約400mg足りない）、
2杯で約3,100mgとなり目標量を超えます。食塩相当量は2杯でも0.12gで影響しません。

入力した数量に応じた**合計金額**を、「現在の食事合計：○g」の横に表示します
（「その他（自由入力）」は金額に含まれません。プロテインの粉代も含みません。
粉代は③の下の「1週間の型の栄養」のまとめに、別立てで出しています）。

### 1週間の型（初期値の自動入力）

毎日その日の型が「③ 今日の食事」に自動で入ります。実際に食べたものが違えば数量を書き換えてください
（書き換えた内容はその日のうちは保持され、翌日また型に戻ります）。

**骨格は「サバ缶＋ご飯＋プロテイン」、外食は週1日だけ**です。

| 曜日 | 朝食 | 夕食 | 自動で決まるもの |
|---|---|---|---|
| 日 | すき家 まぜのっけ朝食（17.1g/300円） | **自宅** サバ缶（31.7g/268円） | ご飯・オリーブオイル・たんぱく質の候補 |
| 月 | すき家 まぜのっけ朝食 | **自宅** サバ缶 | 同上 |
| 火 | すき家 まぜのっけ朝食 | **自宅** サバ缶 | 同上 |
| 水 | すき家 まぜのっけ朝食 | **自宅** サバ缶 | 同上 |
| **木** | 吉野家 ハムエッグ納豆定食（24.1g/468円） | なか卯 親子丼（30g/450円） | 同上（＋吉野家の無料ご飯。入るかどうかも自動計算が決める） |
| 金 | すき家 まぜのっけ朝食 | **自宅** サバ缶 | 同上 |
| 土 | すき家 まぜのっけ朝食 | **自宅** サバ缶 | 同上 |

**毎日（間食／昼食）**：トマトジュース2杯（`autoDaily` で固定）
**木曜以外**：ノンオイルドレッシング1ふり

**バナナとミックスサラダは `WEEKLY_PLAN` では固定していません。**どちらも自動計算の対象で、
その日の栄養バランスから決まります（バナナ0〜3本・運動した日は1本以上／ミックスサラダ0〜3皿）。
運動を入力した標準日はバナナ2本・サラダ1皿、休養日はバナナ0本・サラダ1皿です（v.162の実測）。

サバ缶は**週6缶**（1缶あたり DHA+EPA 約2,850mg）です。

#### 牛丼・牛めし・豚丼は型から外しました

| 品目 | たんぱく質 | 飽和脂肪酸 | たんぱく質10gあたりの飽和 |
|---|---|---|---|
| すき家 牛丼 | 21.7 g | 9.4 g | 4.3 g |
| 吉野家 豚丼 | 14.4 g | 7.1 g | 4.9 g |
| 松屋 牛めし | 17.1 g | 11.6 g | 6.8 g |
| なか卯 親子丼 | 30 g | 4.8 g | 1.6 g |
| サバ缶 | 31.7 g | 4.2 g | 1.3 g |

丼・牛めしは**飽和脂肪酸が重いわりにたんぱく質が入りません**。この3品を週3回入れていたのが
以前の型で、日曜104.3g・水曜87.8g・土曜113.7g、飽和脂肪酸16.3〜18.8g、食塩7.3〜9.1gという
結果になっていました。**LDL対策と筋肥大を同時に狙う標準型としては不適切**なので外しています。

**`FOODS` には残してあります**（食べる日は手で `1` を入れてください）。③の入力欄に
「1週間の型からは外しています（食べる日は手で1を入れてください）」と出ます。
松屋のみそ汁（1杯で食塩1.5g）も同じ理由で型には入れていません。

#### 木曜に外食を2食まとめている理由

外食は**ハムエッグ納豆定食（24.1g・飽和4.2g）を第一候補、親子丼（30g・飽和4.8g）を第二候補**
としています。この2つを**同じ日**に置いているのは、卵の上限のためです。

- **卵は1日2個まで**で、**メニューに含まれる卵も数えます**（`eggs` 指定）。
  まぜのっけ朝食・ハムエッグ納豆定食・親子丼にそれぞれ1個ぶん含まれます
  （型には入れていない塩さば得朝定食・ロースかつ重も1個ぶんです）
- そのため「まぜのっけ朝食＋親子丼」の日は、その2食だけで卵2個を使い切り、
  **卵を1個も足せません**。まぜのっけ朝食は17.1gとたんぱく質が少ないぶん、
  たんぱく質を候補で埋めることになり、食塩と飽和脂肪酸の余裕を削ります
- 「ハムエッグ納豆定食＋親子丼」は 24.1g ＋ 30g で、その2食だけで54.1gが入ります
  （定食なので、エネルギーが足りない日には吉野家のご飯も無料で1杯付きます）

台所を使わない日が1日できる、という副次的な利点もあります。
親子丼の日を分けたい場合は、`WEEKLY_PLAN` の曜日を入れ替えてください。

#### 卵は自動計算の対象に戻しました（v.144）

長いあいだ「型では追加しない」扱いにしていました。たんぱく質10gあたりの飽和脂肪酸が
2.7gと効率が悪く、積極的に足す理由がないためです。**v.144 で自動計算の対象に戻しました。**
全栄養素を同時に見る方式では、卵は**たんぱく質6gと脂質5.2gを同時に足せる数少ない品目**で、
脂質が20%の線に届かない日に効くためです。飽和脂肪酸15gの線は越えないので、
余裕の無い日には選ばれません。**上限は1日2個のままで、メニューに含まれる卵も数えます**
（木曜はハムエッグ納豆定食と親子丼で2個ぶん使うため、自動でも0個です）。

#### 自動で決まる品目の性格

曜日で固定しているのは**外食メニュー・サバ缶・ドレッシング・トマトジュース**だけです。
残りは毎日決め直します（決め方は「自動計算は『全部の栄養素を同時に見て』〜」を参照）。

| 品目 | 主に効く先 | 範囲 |
|---|---|---|
| **ご飯（0.5合）** | エネルギー | 0〜6杯（0〜3合） |
| **オリーブオイル** | 脂質（一価不飽和） | 0〜7さじ（0〜28g） |
| **ミックスサラダ** | 食物繊維・油の置き場所 | 0〜3皿 |
| 無脂肪ヨーグルト／納豆／ツナ缶／サラダチキン | たんぱく質 | 4／3／2／2 |
| **低脂肪牛乳** | たんぱく質 | 0〜3杯（1杯200ml） |
| **全粒パン** | エネルギー・食物繊維 | 0〜3枚 |
| **シリアル** | 食物繊維・エネルギー | 0〜2食（1食30g） |
| **卵** | たんぱく質＋脂質 | 0〜2個（メニュー分を引いた残り） |
| **バナナ** | エネルギーの細かい調整 | 0〜3本（運動した日は1本以上） |
| **アーモンド** | 脂質・食物繊維 | 0〜10粒（1粒＝1.0g） |

- **ご飯はエネルギーの調整手段**です（0.5合＝257kcal・33円・飽和0.1g）。
  1杯で257kcal動くので刻みが粗く、**その前後をバナナ（77kcal）とサラダ（12kcal）で埋めます**
- **ご飯だけは、15gでどう組んでも収まらない日に限り、上限の17g（`SAT_LIMIT`）まで許します。**
  ふだんの探索は合計も15gで止めます（`satCap`）。15gで組める点が1つも無かった日だけ、
  ご飯のぶんを17gまで見逃して探し直します。
  候補と油を15gで止めているのは、それらがたんぱく質・脂質のために選ばれていて
  **代わりがある**からです。ご飯はエネルギーの唯一の調整手段で代わりが無く、しかも
  1杯あたりの飽和脂肪酸は0.1g（自宅6杯＋店1杯でも0.7g）しかありません。
  0.1gのために257kcalを捨てると、以前の「献立が1日1,993kcalしか供給しない」状態に
  逆戻りします。**ただし上限の17gは自動計算では絶対に越えません**
- **1食あたり2杯（1合）まで**（`slotLimit`）で、**その日に自宅で食べる食事の数**を掛けた数が上限です。
  朝食も夕食も外食で昼食も無い日（2食の設定）は置き場所が無いので**0杯**にします
  （丼・定食にご飯が付くため、入れると二重計上になります）

#### `slotLimit` は「人が1食で食べられる量」で決めます（v.158）

**この値は 1杯（0.5合）から 2杯 → 3杯 → 4杯 と3回引き上げられていました。**
理由はどれも「自宅の夕食が700〜900kcal足りない」「−594→−436kcalに改善」で、
**食べられる量かどうかを基準にした回が1度もありません。**
その結果、⑤に「昼食：ご飯4杯」＝**1食で2合**と出ていました。

v.158 で **2杯（1合＝茶碗2杯）** に戻しました。
**栄養は1gも変わりません** — 1日の杯数は同じで、1食に寄っていたものが2食に分かれるだけです
（実測：昼4杯 → 昼2杯＋夕2杯。たんぱく質122.7g・2,782kcal はどちらも同じ）。

**エネルギーが届かない日は、ご飯を積むのではなく「届かない」と出すのが正しい**という判断です。
そのぶん、この型が供給できるエネルギーは **3,605 → 3,131 kcal** に下がりました（後述）。
- **オリーブオイル**で脂質を埋めるのは、増やす脂を一価不飽和脂肪酸にしたいからです
  （1さじ＝4g・36kcal・飽和0.5g・13円）。卵や肉で埋めると飽和脂肪酸が上がります。
  飽和脂肪酸が15gを超える日は入れません。サラダが無い日は置き場所が無いので0さじです

#### 定食の日の無料のご飯（吉野家・松屋）

定食を食べる日だけ、店のご飯を無料で1杯足せます（`teishoku`）。

| 店 | おかわりできる定食 |
|---|---|
| 松屋 | 得朝牛皿定食 |
| 吉野家 | ハムエッグ納豆定食／塩さば得朝定食 |

入れられる条件は「**その店の定食を食べる日**」だけで、**0杯か1杯かは自動計算が決めます**
（上の「ご飯のおかわり」を参照）。置く時間帯はその定食と同じ枠なので、木曜なら朝食に入ります。

#### 自宅の食材をどの枠に置くか

自宅の食材は「外食に持ち込めない」ため、外食の食事には配分できません。
そこで `homeMealDay(slot, st)`（その枠に自宅以外のメニューが入力されていない日）で判定し、
食事ごとに置き場所を決めます。**昼食には外食メニューがない**ので、3食の日の昼食は必ず自宅です。

| その日 | 朝食 | 昼食 | 夕食 | 間食 |
|---|---|---|---|---|
| 3食・夕食も自宅（日月火水金土） | 外食メニュー | ご飯・ヨーグルト・トマトジュース・シリアル | サバ缶・サラダ一式・アーモンド | なし |
| 3食・夕食は外食（木） | 外食メニュー | 自宅の食材はすべてここ | 外食メニュー | なし |
| 2食（昼食を抜く） | 外食メニュー | — | 外食または自宅 | 納豆・卵・トマトジュース |

**3食の日は「間食」の行が出ません。**自宅の食材が昼食と夕食に分かれるためです。

ご飯（`spread:true`）は、その日自宅で食べる食事のうち、**たんぱく質の少ない枠から順に**配ります
（v.154。以前は食事の数で均等に割っていました）。1食に置ける杯数は `slotLimit`＝**2杯（1合）**までです。
自宅の夕食の日はご飯4杯なので、**昼2杯・夕2杯**に分かれます。

#### 「食べる量」を持たせました（v.159）

**v.158まで、このツールは重さという概念を持っていませんでした。**
`FOODS` にあるのは たんぱく質・脂質・飽和・食塩・炭水化物・食物繊維・エネルギー・価格 の8項目だけで、
**何gの食べ物になるかを一度も計算していません**でした。だから7つの帯さえ満たせば、
嵩がいくら増えても探索は平気で選びます。実測で **1日 約3.0kg、昼食だけで1.37kg** という
献立を出していました（利用者の「多すぎて食べきれない」で気づきました）。

何かを絞っても解決しません。ご飯を半分にする実験では、ヨーグルト・パン・バナナが増えて
**総量はむしろ増えました**（2,932g → 2,972g）。

| 入れたもの | 何をするか |
|---|---|
| `GRAM` | 1単位あたりの実重量（g）。**すべて見積り**で、栄養の計算には一切使いません |
| `BULK_AIM` 2,500 | 1日に食べる量の目安。**合否には入れません**（越えても✕にしない） |
| `BULK_W` 1/200 | 探索の重み。目安を超えたぶんだけ点数に足し、**同じ点数なら軽いほうを選ばせる**。食費より重く、食塩・飽和の余裕より軽い |

**ハードな上限にはしていません。**7項目すべてを満たす組み合わせのうち最軽量を探しても
2,552gだったので、2,500gを割れない日が普通にあるためです。

**④に「食べる量」の行**（1日の合計と、多い順に3品目）、
**⑤の目安量の下に各食事の重さ**を出します。

**効果（平日・体重74.4kg・筋トレ8種目の実測）**

| | v.158 | **v.159** |
|---|---|---|
| 1日の合計 | 3,045 g | **2,770 g** |
| 朝食 | 550 g | 550 g |
| 昼食 | **1,374 g**（v.157時点） | **746 g** |
| 夕食 | — | **834 g** |

重さは `GRAM` に1か所でまとめてあり、**調理後の重さ**で数えます
（オートミールは乾燥30g→約100g、ご飯0.5合は米75g→炊きあがり165g）。
プロテインは粉と水を別に数えます。
「その他（自由入力）」と自分で足した品目には重量が無いので0として扱います。

#### 自宅の食材は均等に分けます（`even`・v.158）

**それまでは「いちばん不足している枠へ1単位ずつ入れる」貪欲法だけでした。**
この置き方は嵩を考えないので、**ヨーグルト4杯が全部昼食、サラダ3皿が全部夕食**、
という寄り方をします。利用者からの指摘で気づきました。

次の5品目に `even` を付け、**自宅の食事が2つ以上ある日は均等に割る**ようにしました。

| 品目 | 例（平日・自宅は昼と夕） |
|---|---|
| ミックスサラダ | 3皿 → 昼1・夕2 |
| ノンオイルドレッシング | 1ふり → 夕1 |
| オリーブオイル | 6さじ → 昼3・夕3 |
| トマトジュース | 2杯 → 昼1・夕1 |
| ~~無脂肪ヨーグルト~~ | **v.159で外しました**（下記） |

割り切れない分は**後ろの食事**へ寄せます（サラダ一式を夕食に置く慣習に合わせるため）。

上の表は分割そのものの例です。**いまの標準日（平日・筋トレ8種目）はミックスサラダが1皿**なので、
下の「サラダ一式は同じ食事にそろえる」が効いて、**オリーブオイル6さじはサラダのある夕食へまとまります**。
均等に分かれるのはトマトジュース（昼1・夕1）だけです。

**オリーブオイルからは `homeSlot:'l'`（昼食に固定）を外しました。**
固定されていると分けられず、7さじが1食にまとまっていたためです。

**無脂肪ヨーグルトだけは v.159 で `even` から外しました。**
1杯4.6gとたんぱく質を持つので、均等に割ると**たんぱく質が夕食に寄ります**
（サバ缶31.7gが夕食に固定されているため）。

| | 朝 / 昼 / 夕 | 1食の目安（体重×0.3〜0.6g） |
|---|---|---|
| ヨーグルトも均等（v.158） | 17.1 / 20.5 / **48.3** | 21.8〜43.5 → 夕が超過 |
| **ヨーグルトを外す（v.159）** | 17.1 / 24.6 / **43.7** | **ほぼ収まる** |

外すと貪欲法が「たんぱく質の少ない枠」へ置くので、**ヨーグルトが balancer として働きます**。
代わりに1食へ寄る（最大4杯＝400g）ので、そこは「食べる量」の表示で見ます。

**自宅の食事が1つしかない日は、この分割は効きません**（木曜は昼食だけ、
2食の設定の日は「間食」にまとめる、という既存の扱いをそのまま残しています）。

**ミックスサラダ・ノンオイルドレッシング・オリーブオイルは同じ食事にそろえます。**
配分したあとにドレッシング類をサラダのある食事へ寄せます。
サラダが2つの食事に分かれている日は、どちらにもサラダがあるので寄せ直しは起きません。
サラダが1食だけの日は、油とドレッシングがその食事へ移ります。

### 1週間の型の栄養（合格条件と実測値）

③の「1週間の型」の下に、**各日の栄養と週平均、そして各日の合否**を出します。
④と同じ関数（自動計算・プロテイン・各栄養素の合計）を通しているので、
表に出る数字とその曜日に実際に計算される数字は一致します。

**表は2つに分けています。**運動は曜日で固定していないので、
「食事だけで決まる値」と「その日の運動しだいで決まるエネルギー」を混ぜないためです。

| 表 | 中身 | 運動との関係 |
|---|---|---|

#### 栄養条件と食費条件は分けて出します（v.157）

表の下のまとめは、**2行に分けています。**

> **栄養条件：◎ 7日すべて満たしています**（たんぱく質・食塩・飽和脂肪酸）。
> **食費条件：✕ 1日平均 1,156円**（目安 1,000円／**+156円**）。　週の合計 8,093円。

**それまでは1行で「◎ 食事の条件は7日すべて満たしています。週の食費 8,093円（…目安 1,000円）」
と並べていました。**◎ のすぐ横に目標を超えた金額が出るので、**全体として合格に見える**
という外部レビューの指摘を受けたものです。

**判定そのものは変えていません。**◎／✕ は以前からたんぱく質・食塩・飽和脂肪酸の3つだけを見ていて、
**食費は判定に入っていませんでした**（数字を並べていただけです）。いまはそれを明示しています。

食費が目安を超えている日は、次の1行も添えます。

> 食費は**合否を分けて出しているだけで、献立の組み立てには制約として効かせていません**。
> 自動計算のなかでは「同じ点数なら安いほう」という最後の判断材料です。

**`WEEK_COST_AIM` は探索の制約ではありません。**探索のなかで食費は `COST_W`（重み 1/5000）という
いちばん軽い同点崩しとして効くだけです。**「1,000円を満たせないのに栄養を優先している」のではなく、
そもそも制約にしていない**、という状態を画面にも書いてあります。

### 配分のルール

**運動直後はプロテインとバナナだけ。**運動した日はバナナを運動直後の枠に固定し、
他の食品は一切配分しません。糖質を入れることで、摂ったたんぱく質がエネルギーに回されるのを防ぎます。
**バナナの本数は自動計算で決まります**（0〜3本。運動した日は1本以上）。
標準日は2本で、その全部が運動直後の枠に入ります（木曜は3本）。
運動していない日のバナナは通常どおり食事に配分されます。

**プロテインを2回に分ける日は、バナナも2回に振り分けます。**奇数のときは1回目を多くします
（3本なら 運動直後2本・2回目1本）。1回だけの日はすべて運動直後です。

**朝食メニューは朝食の枠、夕食メニューは夕食の枠にだけ**配分されます（`lock` 指定）。
曜日で固定しているメニュー（`fixedMenu`）は、④の早見表・組み合わせ提案・減らす提案の
いずれの対象にもしません。増減させる前提のものではないためです。

配分しきれない分があるときは、スケジュール表の下に「配分できませんでした」と警告が出ます
（その分も「食事から摂取」の合計には含まれます）。

食品ごとに1日の入力上限を設けることもできます（`FOODS` の `max`）。上限を超える値を入力すると
自動で切り詰められます。現在これを使っているのは**卵（1日2個）**だけです
（メニューに含まれる卵も数えます）。

### ⑤ 時間帯別の摂取スケジュール

初期状態は**食べるものだけの簡潔な表**です（`#schedDetail` がオフ）。
各行は「時間帯／目安量／内容」だけになり、iPhoneの画面1枚に収まります。

**「くわしい説明を表示する」**をオンにすると、食べる順番の案内・過不足の一言・
就寝前の注意など、これまでの説明がすべて出ます。オフでも⚠マークの警告
（朝食メニューの注文期限、間食が就寝前にかかる、配分できなかった品目）は残します。
設定はブラウザに保存され、設定リンクでも他の端末へ運べます。

## 計算ロジック

### 1. 目標たんぱく質

```
目標 = 体重 × 基本係数（初期値 1.65 g/kg）
```

**運動量による加算はしません。**72.5kgなら運動した日も休んだ日も **119.6g** です。

以前は「基本係数1.5 ＋ 運動量スコア × 0.30（上限1.8）」という加算方式でしたが、やめました。
筋トレの総負荷量からたんぱく質の必要量を細かく算出できる根拠が無く、レジスタンストレーニング中の
摂取量はメタ解析で **約1.6g/kg/day を超えると除脂肪量への追加効果が見られない**ためです。
1.65g/kg はその目安を少し上回る、扱いやすい標準値として選んでいます。

| 基本係数 | 想定 | 72.5kgでの目標 |
|---|---|---|
| 1.2 | 運動習慣がない／たんぱく質制限あり | 87 g |
| 1.5 | 維持〜微増 | 108.8 g |
| **1.65（初期値）** | **筋肥大を狙う標準** | **119.6 g** |
| 1.8 | 減量しながら筋肉を落としたくない | 130.5 g |
| 2.0 | 減量幅が大きい／体脂肪をさらに絞る | 145.0 g |

**減量期は係数を上げてください。**エネルギーを削る時期は除脂肪量を守るために
たんぱく質を増やす必要があり、目安は **1.8〜2.4 g/kg**（除脂肪量を基準にするなら 2.2〜2.5 g/kg）です。
1.65のままだと不足します。

この型で実際にどこまで届くかを測った結果です（体重72.5kg・月曜の型・筋トレ8種目を初期値どおり）。

| 基本係数 | 目標 | 実際に届く量 | 粉 | 飽和 | 食塩 | 食費 |
|---|---|---|---|---|---|---|
| 1.8 | 130.5 g | 131.3 g | 5杯 | 13.1 g | 6.6 g | 1,064 円 |
| 2.0 | 145.0 g | 145.1 g | 5杯 | 14.4 g | 7.0 g | 1,107 円 |
| 2.2 | 159.5 g | 158.7 g | 6杯 | 14.6 g | 7.3 g | 1,177 円 |
| **2.3** | 166.8 g | **165.1 g（1.7g 足りないが誤差の範囲）** | 6杯 | 14.2 g | 7.3 g | 1,329 円 |
| 2.4 | 174.0 g | **168.9 g（5.1g 足りない）** | 5杯 | 14.8 g | 7.4 g | 1,394 円 |
| 2.5 | 181.3 g | **167.9 g（13.4g 足りない）** | 6杯 | 14.8 g | 7.4 g | 1,337 円 |

**限界は 2.3 です**（`TOLERANCE` 3g の範囲に収まるところまでを「届いた」と数えています）。
v.156 でいったん 2.4 まで上がりましたが、**v.158 で 2.3 に戻りました**。
供給の上限は **177.9g → 168.9g**。下がった9gは、ご飯の1食あたりの上限を
2合から1合に戻して**1日あたり2杯（4.5g×2＝9g）減ったぶん**とちょうど一致します。

**止めているのは「粉の6杯」と「食塩7.5gの線」の2つ**です。
2.4・2.5の行でも飽和脂肪酸は14.8gで、先に当たるのは食塩のほう（7.4g）です。

**SAVASのときは2.0が限界で、2.2では11.2g足りませんでした。**Bproは1杯10.4gと
たんぱく質が多く、飽和脂肪酸も1杯0.333gと小さいので、粉で埋められる量が増えました。

**運動量はエネルギー側に反映します。**運動量スコアはそのまま残っていて、
消費エネルギーの計算と、④のバッジ（休養日／軽運動日／トレーニング日／ハード日）に使います。

```
運動量スコア = 総負荷量 ÷ 6,500kg ＋ ウォーキング換算距離 ÷ 10km   （上限 100%）
ウォーキング換算距離 = ウォーキングkm ＋ サイクリングkm × 0.35
```

- 総負荷量 = Σ（重量 × 回数 × セット数）※チェックを入れた種目のみ
- サイクリングは同距離あたりの負荷が低いため、係数 0.35 でウォーキング換算します。

運動量が増えたら**たんぱく質ではなく主に炭水化物**を増やす、という設計です。

### 2. 最低ライン

目標は「ここまで摂れれば理想」という上限であり、下回ったら失敗という線ではありません。
そのため「④ 計算結果」には目標とは別に **最低ライン（体重 × 1.2 g/kg）** を表示します。

- 最低ラインを超えていれば「この水準を保てていれば筋肉の維持には足ります」と表示
- 下回っている場合は、そこへ届かせるための不足量と食品の組み合わせを提示

足りなかった分を翌日に取り返すことはできないので、評価は1日単位ではなく
1週間の平均で見る前提の表示にしています。

#### 1食あたりのたんぱく質は「上限」ではなく目安

```
体重 × 0.40 g … ◎ 筋タンパク合成がほぼ最大になる目安（`MEAL_P_OPT`）
体重 × 0.30〜0.60 g … ○ そのままで問題なし（`MEAL_P_LO` 〜 `MEAL_P_MUCH`）
体重 × 0.60 g 超   … △ 分散できるなら分散（`MEAL_P_MUCH`）

72.5kgなら **29.0g が目安**、**21.8〜43.5g なら問題なし**、**43.5g超で「分散できるなら」**です。
```

1回で筋タンパク合成がほぼ最大になるのが**体重あたり0.4g前後**です
（Schoenfeld & Aragon 2018）。**これを超えた分が使えなくなるわけではありません。**

**評価帯は体重に連動させています**（v.133）。固定のgにすると、1食の目安量のほうは
体重から出ているのに評価帯だけが取り残され、体重の大きい人では
0.4g/kgどおりの食事を「多い」と判定してしまうためです
（`WEEK_P_MIN` を固定120gにしていたのと同じ型の問題でした）。

以前は「1回40gが上限」として、超えた分を⑤で**回し分の行**に分け、3時間空けて摂るように
組んでいましたが、やめました。夕食が42gになったからといって2gを3時間後に食べるのは
食事管理として不自然で、「40gを超えたたんぱく質は使えない」という誤解も招くためです。
いまは**自動で分割せず**、体重×0.6g（72.5kgなら43.5g）を超えた食事にだけ「分散できるなら」と一言添えます。

「⑥ 食事・栄養のポイント」は、**その日の状態 → 一般的な心得**の順に並べます。
先頭に最低ラインの判定、その次に過不足の状態（「食事の追加は不要です」「あと ○g を追加してください」
「○○を減らしてください」）と食事の入力漏れへの注意を置き、そのあとに①〜⑥の解説が続きます。

#### 65歳になったら見直すこと

**加齢で同化抵抗性が進むと、同じ量のたんぱく質でも筋タンパク合成の反応が鈍ります。**
いまは55歳なので調整を入れていませんが、**65歳を目安に次を見直してください**。

| 見直す値 | いま | 65歳以降の目安 | 理由 |
|---|---|---|---|
| **`MEAL_P_OPT`**（1食あたり） | 0.40 g/kg（72.5kgで29g） | **0.50〜0.55 g/kg**（36〜40g） | 若年では20〜25gでMPSがほぼ最大になるが、高齢者では40g程度まで増やすほうが総アミノ酸供給量の面で有利 |
| **基本係数**（1日あたり） | 1.65 g/kg | **そのままで可** | 高齢者向けガイドラインの 1.2〜1.6 g/kg を、1.65 はすでに上回っている |

**効くのは1日の総量より「1回あたりの量」です。**総量が足りていても1回が小さいと、
1回ごとの立ち上がりが鈍くなります。`MEAL_P_OPT` を上げれば、⑤の一言・⑥のポイント①・
⑤の「分散できるなら」の線がすべて自動で追従します（体重連動なので、体重を変えても崩れません）。

あわせて **プロテインの1回あたりの上限（`MAX_PER_SERVE` 3杯＝31.2g）も見直しの対象**になります。
0.55 g/kg なら1回40gなので、粉だけで届かせるには4杯（41.6g）が要ります。
現実的には**食事と組み合わせて1回分を作る**ほうが、食費の面でも無理がありません。

**①の「年齢」は基礎代謝（Mifflin-St Jeor）の計算にしか使っていません。**
年齢を65に変えても1食の目安は動かないので、**この見直しは手で入れる必要があります**。

### 3. 食事回数（2食 / 3食）

「① 基本設定」で3つから選べます。

| 選択肢 | 抜く食事 | 配分 |
|---|---|---|
| 2食（朝食・夕食） | 昼食 | 残りを2つの枠へ |
| 2食（昼食・夕食） | 朝食 | 残りを2つの枠へ |
| **3食**（初期値） | — | 残りを3つの枠へ |

**単純な等分ではありません**（v.154）。外食のメニューで決まる枠はその実際の量を目安とし、
余りを自宅の食材を置ける枠へ配り直します（「時間帯別スケジュール」を参照）。

- 抜く食事に固定された食品は、残っているもう一方の枠へ回されます
- スケジュール表には抜く食事の行が「昼食（抜く）」のように残り、間隔が空く旨を案内します
- 「⑥ 食事・栄養のポイント」の分散に関する説明も、選んだ型に合わせて切り替わります
- 昼食を抜く型では、朝食から夕食までの基本の間隔を8時間にしています

### 4. 運動量に比例するのはエネルギー（糖質）

たんぱく質の必要量は運動量に比例しません（1.6g/kg前後で頭打ち）。
一方で**エネルギーの必要量は運動量に比例して増える**ため、こちらは上限を設けずに算出します。

```
必要エネルギー = 基礎代謝（Mifflin-St Jeor） × 1.63 ＋ 運動の正味消費 ＋ 補正
運動の正味消費 kcal = 総負荷量 × 0.032 ＋ 体重 ×（ウォーキングkm × 0.5 ＋ サイクリングkm × 0.28）
補う糖質 g          = 運動の正味消費 kcal × 0.5 ÷ 4
補正 kcal           = ①の「必要エネルギーの補正」（初期値0・±600）
```

#### 「BMR × 1.63 ＋ 入力した運動」は Protein Sync の推定モデルです

**この式を「医学的に正しい消費エネルギーの求め方」としては扱いません。**
食事量を決めるための実用的な目安として、このツールが採る推定モデルです。

**① 係数1.63の中身（活動レベル1.50 ＋ 増量の余剰0.13）**

掛ける係数 `ACTIVITY` は **1.63** で、これは2つを1つにまとめた値です。

- **活動レベル 1.50**：日本人の食事摂取基準の身体活動レベル **I（低い）**。
  「生活の大部分が座位で、静的な活動が中心の場合」の値
- **増量の余剰 0.13**：週 +0.2kg ぶん（0.2 × 7,200 ÷ 7 ≒ 1日 +206kcal。
  基礎代謝1,564kcalに対して +0.13）

以下は前半の**活動レベル1.50**についての説明です（余剰のほうは「実測とのずれ」を参照）。
1.50を**座位中心の生活を想定した値として採用**し、そこへ**入力された運動の正味消費**を
加えるのが、このツール独自の推定モデルです。

ただし、活動係数は本来「日常生活の活動量をまるごと1つの数字で表した近似値」であり、
**個人の日常活動量を完全に表すものではありません。**
仕事・家事・移動などの量は人によって違い、1.50がその人のベースラインと一致する保証はありません。
また「活動係数方式」と「安静時代謝＋日常の活動＋運動＋食事誘発性熱産生を積み上げる方式」は、
本来まったく同じものではありません。

そのため、**必要エネルギーはあくまで推定値**として扱ってください。
体重・身長・年齢から自動で決まる値で、ずれる分は①の**「必要エネルギーの補正」**で
手当てします（下の「実測とのずれ」）。
④のエネルギー行にも「推定 ○kcal」と書いてあるのはこのためです。

**なぜこの形にしたか**（72.5kg・177.4cm・55歳男性、BMR 1,564kcal）

| 方式 | 計算 | 筋トレのみ | ＋ウォーキング10km |
|---|---|---|---|
| **A：BMR × 活動係数だけ** | レベルII（ふつう・1.75）＝ 2,737 | 2,737 | 2,737（運動量が変わっても動かない） |
| **B：BMR × 1.63 ＋ 運動の正味消費**（採用） | 2,549 ＋ 運動 | **2,763** | **3,125** |

**方式Bを採用しています。**方式Aは「自分がレベルIIなのかIIIなのか」を主観で選ぶことになり、
しかも運動量を変えても数字が動かないので、このツールの目的
（その日の運動に応じてご飯の杯数を調整する）に合いません。
どちらが「正しい」かではなく、**日ごとの調整に使えるかどうか**で選んでいます。

**② 運動の側は「正味（METs−1）」で数えます**

このモデルの中で辻褄を合わせるために、運動の消費は正味で数えます。
基礎代謝 × 1.63 の中には、運動している時間帯の安静時代謝もすでに入っているので、
総消費（グロス）をそのまま足すと、その分を二重に数えることになります。

| 種目 | 以前 | いま | 根拠 |
|---|---|---|---|
| 筋トレ（総負荷量1kgあたり） | 0.04 | **0.032** | 5METs・約35分とみなした正味 (5−1)×体重×時間 から、**体重73.5kgだった当時**に置いた係数（当時の型 5,659×0.032＝181kcal相当。いまの初期値 6,682.5kg なら214kcal）。体重が変わっても据え置き |
| ウォーキング（体重1kg・1km） | 0.5 | 0.5（変更なし） | 時速5km＝3.5METs。(3.5−1)×72.5×1時間 ÷ 5km ＝ 体重×0.5。**もともと正味** |
| サイクリング（体重1kg・1km） | 0.28 | 0.28（変更なし） | 時速15km・約5.2METs相当。同じく正味 |

有酸素の2つはもともと正味の値で、**筋トレだけがグロスのままだった**ので、
0.04（当時の型でグロス226kcal相当）を0.032（同じく正味181kcal）に直しています（約45kcalぶん）。

なお筋トレの消費エネルギーは、種目・重量・回数・インターバル・実施時間・強度で変わるため、
**総負荷量だけで正確に出せるものではありません。**ここも目安です。
精度を上げるより、上の**体重推移による補正**を使うほうが実用的だと考えています。

#### 画面にも「推定」と書きます（v.157）

**それまで「推定」は合計にしか付いておらず、運動の数字そのものには付いていませんでした。**
すぐ横の②には「総負荷量 6,682.5 kg（重量×回数×セット数の合計）」という**正確な実測値**が出るので、
そこから出した214kcalも確かな消費量に読めてしまう、という外部レビューの指摘です。

いまは**数字の隣に「（推定）」を付け**、運動を入力した日には④の栄養成分表の下にこう出します。

> **運動の消費エネルギー（約214kcal）は推定値です。**筋トレのぶんは
> **総負荷量に比例させたこのツール独自のモデル**で出しています。
> 実際の消費は種目・セット間の休憩・トレーニングの密度で変わり、研究でも **3〜8 METs** と幅があります。
> 実測とずれるようなら、①の「必要エネルギーの補正」で合わせてください。

（実際の画面には、モデルの係数「総負荷量1kgあたり `KCAL_PER_VOLUME` kcal」も併記されます。）

有酸素だけの日は「有酸素のぶんは『体重1kg・1kmあたり』の近似です」に切り替わり、
運動が0の日はこの注記も「（推定）」も出しません。

**値そのものは変えていません。**「筋トレは固定 +100〜150kcal にする」という案も出ましたが、
総負荷量と消費エネルギーに一定の関係を示す実測（10,000kg→247kcal／20,000kg→484kcal）があり、
いまの係数 0.032 kcal/kg はそこから出る 0.0247／0.0242 よりやや大きい程度で、桁としては外れていません。
**値は残し、性格の表示だけを直す**という判断です。

**③ 本当の問題はエネルギー計算ではなく献立でした**

必要量の推定が45kcalずれていたことより、**献立が1日1,993kcalしか供給していなかった**ことのほうが
はるかに大きい問題でした。いまの型では週平均2,758kcal（必要量2,763kcalに対して−5kcal）になっています。

#### 実測とのずれ（①の「必要エネルギーの補正」で手当てする）

活動係数は集団の平均から来た値なので、**同じ体重・身長・年齢でも実際の必要量は
数百kcalずれます。**ここを埋めるために、**①に「必要エネルギーの補正 (kcal)」を1つ**置いています。

**増量の余剰はこの欄ではなく `ACTIVITY` に入れてあります**（v.131）。
`ACTIVITY` 1.63 ＝ 活動レベル1.50 ＋ 増量の余剰0.13 で、基礎代謝1,564kcalに対して
**+203kcal／日（週 +0.20kg 相当）**です。補正欄は0のままで構いません。
目的を変えるときは `index.html` の `ACTIVITY` を直してください（維持1.50／減量 約1.30）。

```
必要エネルギー = 基礎代謝 × 1.63 ＋ 運動の正味消費 ＋ 補正（kcalAdj）
```

- 初期値は **0**（＝計算式どおり）。範囲は **±600kcal**（`KCAL_ADJ_CAP`）
- 欄の下に **［−100］［−50］［＋50］［＋100］［0に戻す］** のボタンがあります。
  **iPhone対策です。**iOS Safari は `type="number"` にスピナー（▲▼）を出さず、
  `inputmode="numeric"` のテンキーには**マイナスのキーがありません**。
  そのままだと iPhone から負の補正を入れられないので、キーボードを使わない経路を用意しています
  （PCではスピナーでも直接入力でも構いません）
- **ご飯の自動計算にもそのまま効きます**（+200kcal入れればご飯が1杯増える日があります）
- ④のエネルギー行に「（基礎代謝 1,564 × 1.63 ＋ **運動 約214kcal（推定）** ＝ 推定 2,763kcal ／ 手動で +200kcal 補正）」と根拠が出ます
- 設定の扱いなので、日付が変わっても消えません。設定リンクにも載ります

**入れる値の決め方。**体重が狙いどおりに動かない日が2週間以上続いたら、
**体重1kg ≒ 7,200kcal** としてずれを1日あたりに直します。

```
補正 kcal = （狙いの体重変化 − 実際の体重変化）× 7,200 ÷ 日数
```

例：2週間で狙いより 0.4kg 足りない → 0.4 × 7,200 ÷ 14 ≒ **1日200kcal不足**なので **+200**。

**1日だけの体重差は水分で数百g動きます。**2週間以上の動きで判断してください。

以前は①に「体重の推移で必要エネルギーを補正」（記録した日数・体重の変化・体重の目標・
7日平均2つ・計算ボタン）を置いて、この計算をツール側でやっていましたが、
入力欄6つのわりに使われないため **v.124 で削除**し、**v.125 で補正値そのものを入れる
1欄に置き換えました**。ずれの計算は上の式で手元で行い、結果だけを入れる形です。

なお `ACTIVITY`（1.63）は画面からは変えられません。補正が毎日同じ値で固定するようなら、
`index.html` の `ACTIVITY` 側を直すほうが筋は通ります。

#### 係数の根拠（いずれも目安です）

- **総負荷量 × 0.032**：総負荷量からは直接kcalを出せないため、
  「中強度のレジスタンス運動 5METs」と、当時の型の総負荷量5,659kgが約35分に相当することから
  逆算した係数（安静時を差し引いた正味）。**体重73.5kgだった当時に置いた値で、
  体重を変えても係数は据え置き**です（ずれは①の「必要エネルギーの補正」で手当てします）。
  **総負荷量あたりの係数なので、重量やセット数を変えれば消費も比例して動きます。**
  いまの初期値（6,682.5kg）では 214kcal です
- **ウォーキング 0.5**：歩行・走行で広く使われる「体重1kg・1kmあたり約0.5kcal」の近似
  （72.5kgで10kmなら約363kcal）。METs換算では (3.5−1) METs の正味にあたります
- **サイクリング 0.28**：同じ距離あたりの負荷が低いため、ウォーキングの0.56倍
- **糖質 50%**：「必ず50%」という根拠のある数字ではありません。
  「運動量が増えたらまずエネルギーを補う。炭水化物はその主な候補」という位置づけの目安です

エネルギーが不足すると、摂取したたんぱく質がエネルギー源として使われ、筋肉の材料に回りません。

**たんぱく質の目標は運動量で変わりません**（体重72.5kg・基本係数1.65なら、どの行も119.6g）。
変わるのは推定消費エネルギーと、それを補う糖質の目安、そして**自動で決まるご飯の杯数**だけです。

**筋トレは初期状態では1種目もチェックが入っていません。**その日にやった種目だけ入れてください。

より `slotLimit` のほうが先に効きます）。**上限に達したあとは、シリアル（110kcal）と

この行はエネルギーが必要量を40kcal上回ります。

**必要エネルギー = 基礎代謝 × 1.63 ＋ 正味消費**です。72.5kg・177.4cm・55歳男性なら

### 5. 不足分とプロテインの配分

```
不足 = 目標 − 食事からの合計たんぱく質
```

不足を埋める配分は、次の制約の中から**不足量にいちばん近づく組み合わせ**を総当たりで選びます。

| 制約 | 値 |
|---|---|
| 1回あたりの杯数 | 最大 **3杯（31.2g）** |
| 1日の回数 | **1回（運動直後のみ）**。「1日2回まで摂る」をオンにすると2回 |
| 許容する摂りすぎ | 3 g まで |

**「1回40gまでしか吸収できない」という上限は設けていません。**以前は `ABSORB_CAP = 40` という
定数で1回の量を縛っていましたが、その前提自体が正しくないため削除しました
（実際には `MAX_PER_SERVE` のほうが先に効いていて、40gが計算に影響したことはありません）。

**1回の上限は3杯（31.2g）です**。吸収の限界ではありません（そういう上限はありません）。
1回で **0.4g/kg**（72.5kgで29g）に届かせるための下支えです。
Bproは1杯10.395gなので、2杯では 20.8g・**0.29g/kg** にしかならず、3杯で 31.2g・**0.43g/kg** になります。

**以前は「ロイシン閾値2.5g」も根拠に挙げていましたが、v.152で外しました。**
ロイシン量が閾値を超えれば筋タンパク合成が最大になる、という単純な閾値モデルには異論があり
（2023年の系統的レビューでは明確な閾値は確認されていません）、そもそも
**製品のロイシン量は非公表**で、ホエイの含有率10〜12%からの推定でしかありませんでした。
根拠がはっきりしている **0.4g/kg** のほうに一本化しています。
運動直後の回はバナナとしか組まないため、ここが**1日でいちばん効かせたい回**だからです。

**杯の大きさは製品で変わるので、上限は「たんぱく質のg」で考えて杯数に直します**
（`PROTEIN.maxPerServe`）。製品を変えたときはここも見直してください。
水で溶かすため液体からの加算はなく、
脂質を含まないぶん胃を素早く通過してアミノ酸が早く血中に届きます。
**運動していない日はプロテインを摂りません**（目標分はすべて食事から確保します）。
①で「運動しなかった日もプロテインを摂る」をオンにした場合のみ、休養日も不足分を補います
（最低杯数の縛りはなく、不足がなければ0杯）。

### 2食の日はプロテインを6杯に固定

**2食（朝食・夕食／昼食・夕食）の日は、不足をまずプロテインで埋める**方針とし、
**上限の6杯（3杯×2回・62.4g）に固定**します。⑤には「運動直後」と「2回目のプロテイン」の2行が出ます。

**ただし上限は「1回3杯 × その日に許した回数」を超えません。**
「プロテインを1日2回まで摂る」がオフの日は1回だけなので、固定するのも**3杯**です
（以前はオフでも2回に固定してしまい、①に書いてある上限と食い違っていました）。

- 判定に使うのは**自動計算の候補を除いた不足量**です。候補を足したあとに再計算しても
  杯数が動かないようにするためです（そうしないと「杯数が減る→候補が増える→…」と堂々巡りになります）
- 自動計算の候補を除いた不足が62.4g未満の日は固定せず、自動計算のままにします（粉の摂りすぎを防ぐため）
- 「プロテインの杯数を指定」に入力があれば、そちらが優先されます
- 3食の日はこの固定を行いません

### プロテインにも飽和脂肪酸の線を効かせる

プロテインは1杯あたり飽和脂肪酸 0.333g（Bproの推定値）です。4杯なら1.3g になるので、
**粉の杯数しだいで1日の飽和脂肪酸が動きます。**

v.134 で1回あたりを5杯に増やしたとき、木曜（外食2食の日）が 15.0g → 15.2g となり、
**15gの線を越えました**。当時のたんぱく質の候補とオリーブオイルには15gのガードがあるのに、
**プロテインの杯数（`savasFor`）にだけ無かった**ためです
（v.121 でご飯について直したのと同じ型の抜けでした）。

そこで `capSavasBySat` を足し、**粉にも同じ線を効かせています**。

- 削るのは**2回目から**。**運動直後の回は `MAX_PER_SERVE` を保ちます**
  （1回あたりを増やしたのが目的なので、そこは最後まで守る）
- **筋トレをした日の最低杯数（`MIN_SPOONS_TRAINED` 2杯）より下へは削りません**
- **「杯数を指定」で手動指定した日は適用しません**（指定が最優先）
- 削った日は④に「飽和脂肪酸が15gの線に当たるため、杯数を○杯に抑えています」と出ます

**Bproではこのガードは型のなかでは発動しません**（木曜は 3杯・飽和 14.2g。
上限%を100%にしても不足量のほうが先に効くので3杯のままです）。
1杯あたりの飽和脂肪酸が 0.333g と小さいためです。製品を変えると再び効くことがあるので、ガードは残します。

### 杯数は1回目から先に満たす

複数回に分けるときは、**1回目を上限まで満たしてから2回目に回します**（`dealSpoons`）。
後ろの回には最低 `MIN_PER_SERVE` 杯を残します。

| 合計 | 配分 |
|---|---|
| 2杯 | 2（1回） |
| 3杯 | 3（1回） |
| **4杯** | **3＋1** |
| 5杯 | 3＋2 |
| 6杯 | 3＋3 |

以前は1杯ずつ回り持ちで配っていたため、4杯は 2＋2 になり、
**運動直後の回が1回の上限に届きませんでした**。1回あたりを増やした目的が
達成できていなかったので、配り方をそろえています。

### 筋トレをした日はプロテインが必須

筋トレをした日は、**食事だけで目標に届いていてもプロテインを最低 2杯（20.8g）飲みます**
（`MIN_SPOONS_TRAINED`）。「プロテインの追加摂取は不要です」とは表示されません。
**杯数ではなく「20g前後を1回」で考えた値**です。杯の大きさは製品で変わるので、
製品を変えたときは g に直して決め直してください。

その結果、食事＋プロテインが目標を超える場合は、**食事のどれを減らすとよいかを提案します**。
減らす対象は、その日のタンパク源が多いカテゴリから、1単位あたりが大きいものを選びます。

ただし **現在は朝食・夕食とも曜日で決めたメニュー**（外食またはサバ缶。いずれも `fixedMenu`）で、
バナナ・トマトジュースとあわせて**すべて減らす提案の対象外**です。そのため超過した日は
「1単位が大きい品目しかないため、この日は多めのままで構いません」と表示されます。

目標とのズレが **5g 未満（`DEVIATION_OK`）は誤差として扱い、増やす提案も減らす提案もしません**。
増減で別のしきい値を使うと「減らせ」と「補え」が交互に出てしまうため、両方向でこの値を使います。

### 不足分の埋め方

不足は次の順で埋めます。

1. **プロテイン**（初期値は空欄＝不足量から自動計算。標準日で3杯＝31.2g）
2. **自動計算の候補**（無脂肪ヨーグルト／納豆／ツナ缶／サラダチキンから選ぶ。
   選び方は「③ 今日の食事」の章の「たんぱく質の残りを埋める候補」を参照）
3. それでも残る分は「残り ○g は食事で補ってください」と表示

候補・トマトジュース・バナナ・固定メニューはすべて**減らす提案の対象外**（自動計算または固定のため）
なので、数gの過不足はそのまま残ります。5g未満は誤差として扱うので、通常は指摘も出ません。

さらに増やしたい場合は、固定メニュー以外に食べたものを**「その他（自由入力）」**にg数で入れるか、
「プロテインで賄う上限」を上げてください。

④の早見表（各食品で残りを補う場合の数量と金額）は、**プロテインの杯数のすぐ下・栄養成分表の上**に置いています
（`#altFoods` → `#oSatBox` の順）。たんぱく質の話は続けて読めたほうが分かりやすいためです。
次の制約をかけています。

- **自動計算する品目は出しません。**数量が不足量から決まるため、そこへさらに足す提案は成り立ちません
- **1日の上限がある品目は、その日の残り枠まで**しか提案しません（卵をすでに1個食べていれば提案は1個まで）
- 提案しても不足が残る場合は「**これでも ○g 残ります**」と明示します。
  「プロテインで賄う上限を上げる」案内は、上げて実際に杯数が増えるときだけ添えます
- 対象になる食品が1つも無い場合は、表そのものを案内文に置き換えます

食品を増やせるようにする場合は、`FOODS` に `fixedMenu` を付けない品目を足してください。
`SUGGEST_ORDER` は「固定メニュー・野菜・運動直後固定・自動計算でない、1単位5g以上の品目」から
自動で作られるので、追加した品目はそのまま提案・早見表に使われます。

**1日の上限（卵の2個）は、入力のたびだけでなく計算のたびにも効かせます**（`clampLimits`）。
設定リンクや保存データから上限を超えた値が入ることがあり、
そのままだと④の合計に乗ってしまうためです。

### 判定の段階（④の札）

「基準を満たす／満たさない」の2値ではなく、どのくらい離れているかで書き分けます。

**食塩は v.153 で4段階にしました。**それまで `SALT_CARE`（8.0）という定数は
**定義されているだけで判定に使われておらず**、7.5〜9.0g が一律「やや多い」でした
（7.6g も 8.9g も同じ表示）。外部レビューの「7.5〜9.0が何なのか定義されていない」という
指摘のとおりだったので、定数を実際に効かせています。
**合否の線は 7.5g のまま**なので、週の表の判定と自動計算の挙動は変わりません。

| 栄養素 | ◎ | △ | ⚠ / 🔴 |
|---|---|---|---|
| 食塩相当量 | 7.5g未満「ちょうどよい」 | 7.5〜8.0g「やや多い」／8.0〜9.0g「多い」 | 9.0g超「多すぎる」 |
| 飽和脂肪酸 | 15g以下「良好」 | 15〜17g「上限内」 | 17g超「多い」 |
| エネルギー | ±200kcal「ちょうどよい」 | −200〜−300「やや少ない」 | −300〜−500「筋肥大には不利」／−500超「足りない」 |

「1週間の型の栄養」の合否も同じ線を使います（食塩7.5g未満・飽和脂肪酸15g以下・
エネルギーは−500kcalまで）。たんぱく質だけは週の表のほうで**その日の目標の95%**という線を
別に持っています（`WEEK_P_OK`）。

#### たんぱく質の線は2本あります（v.152で分けました）

| 定数 | 値 | 役割 |
|---|---|---|
| `WEEK_P_RATIO` | 0.99（118.4g） | **自動計算が狙う下限。**探索はここを割らないように組みます |
| `WEEK_P_OK` | 0.95（113.6g） | **週の表で合否を分ける線。**表示だけに使います |

以前はどちらも0.99で、週の表は「毎日 目標の99%以上」でなければ✕でした。
**1.65 g/kg という係数自体にそこまでの精度は無い**ので、0.1g足りないだけで✕にするのは
過度に精密でした（外部レビューの指摘）。

**ただし、探索の下限まで一緒に緩めると実際の摂取量が下がります。**
探索は「113.6gで足りる」と判断して、浮いた余地をエネルギーや脂質の帯に回すためです。
そこで**判定だけを緩め、狙いは目標のまま**にしてあります。
どちらも体重連動の割合で持っています（固定gにすると、体重を変えたときに線だけが取り残されます）。

**どの行にも「多い順に3品目」を添えます**（脂質・飽和脂肪酸・食塩相当量・食物繊維・
炭水化物・エネルギー）。何がその数値を作っているかが分かれば、減らす／増やす相手を
選べるためです。エネルギーの行だけは単位が kcal で、**摂った側の内訳**と
**必要量の内訳**（基礎代謝 × `ACTIVITY` ＋ 運動）を行を分けて並べます。

#### 文面の書式（v.139で統一）

**どの行でも、線までの距離を必ず数値で書きます。**以前は「基準内のとき」だけ書式が
ばらついていて、脂質と炭水化物は何も出ず、飽和脂肪酸は文だけ、食塩とエネルギーは数値あり、
という状態でした。

| 行の型 | 対象 | 外れたとき | 基準内のとき |
|---|---|---|---|
| 越えない線 | 飽和脂肪酸・食塩相当量 | 「○g 超えています」 | 「○g 以下です（**余裕 ○g**）」 |
| 下限〜上限の範囲 | 脂質・炭水化物 | 「あと ○g」「○g 超えています」 | 「目標範囲の中です（**近いほうの線まで 余裕 ○g**）」 |
| 満たす目標 | 食物繊維 | 「あと ○g」 | 「満たしています（+○g）」 |
| 必要量との差 | エネルギー | 「○kcal 足りません／上回っています」 | 「（○kcal 多め／少なめ）」 |

- **範囲の行は「遠いほう」ではなく「近いほうの線」までを出します**（`inRange`）。
  遠いほうを出すと余裕があるように見えるためです。上限ぴったりの日には
  「上限まで 余裕 0g」と出て、張り付いていることが分かります
  （札は「ちょうどよい」のままなので、文が無いと見分けられませんでした）
- **越えない線の行は「あと ○g」ではなく「余裕 ○g」と書きます。**「あと」は
  そこまで埋めてよい枠のように読めるためです。飽和脂肪酸には
  「17g は上限なので、埋めにいく必要はありません」を引き続き添えます

- **飽和脂肪酸の17gは上限であって目標ではありません。**15g以下なら「良好」と出し、
  15gを超えたら「上限までは余裕があるが、LDLを下げたい日は15g以下に」と添えます

#### 飽和脂肪酸の2本の線の意味（v.152で書き分けました）

**15g・17gはどちらも公的基準そのものではありません。**このツールの独自目標です。

| | 値 | 性格 |
|---|---|---|
| 日本人の食事摂取基準の目標量 | **総エネルギーの7%以下** | **エネルギーに連動する**。2,200kcalなら17.1g、この型の実測（約2,758kcal）なら**21.5g** |
| `SAT_GOOD` | **15 g** | LDL対策の保守的な固定値。毎日クリアしたい線 |
| `SAT_LIMIT` | **17 g** | 同じく固定値。どの品目でも絶対に越えない線 |

17gという数字は「2,200kcalの7%」から来ていますが、**実際の摂取エネルギーは2,758kcal前後**なので、
7%Eに連動させれば21.5gまで許されることになります。
**あえて連動させず、低いほうの固定値に留めている**のは、健診でLDLの上昇と
動脈硬化指数3.3を指摘されているためです。

実測は **13.1〜14.2 g ＝ 4.3〜4.6%E**（運動を入力した週。平日13.1g・木曜14.2g）で、
7%Eの基準に対しては十分低い水準です。
ここからさらに1〜2g削るより、**そのエネルギーを何に置き換えるか**のほうが重要になります。
- **たんぱく質を満たすために食塩や飽和脂肪酸を増やす献立は作りません。**
  自動計算の**たんぱく質の候補とオリーブオイル**は、**食塩7.5g・飽和脂肪酸15g**
  （＝毎日クリアしたい線）を越えません。9.0g / 17g は上限であって目標ではないので、
  そこまで埋めにいかない作りにしてあります。
  **ご飯だけは例外で、15gでは止めず上限の17gで止めます**（ご飯は飽和脂肪酸が1杯0.1gと小さく、
  エネルギーの唯一の調整手段のため。詳しくは「ご飯・オリーブオイル・たんぱく質の候補は
  自動で決まります」を参照）。**どの品目でも上限の17gは自動計算では絶対に越えません。**
  手で入れた品目でこの線を越えた日は「やや多い」「多すぎる」と表示します
- **エネルギーの赤字は筋肥大に不利**です。たんぱく質が足りていても、慢性的に
  −300〜−500kcalだと除脂肪量は増えにくくなるため、その旨を本文にも出します

### 6. プロテインで賄う上限

不足の全量を粉で補うと1日の大半をプロテインで摂ることになるため、
**プロテインで賄うのは1日の目標の一定割合まで**とし、残りは食事に回します。
割合は「① 基本設定」で変更でき、初期値は **40%** です（100%にすると不足の全量をプロテインで補います）。

杯数を決めているのは、次の3つのうち**いちばん小さい値**です。

1. その日の**不足量**（食事で足りていれば、そもそも杯数は増えません）
2. **割合の上限**（目標 × この%）
3. **杯数の上限＝1回3杯 × 1日の回数**（2回まで許可していれば**6杯＝62.4g**、1回だけなら3杯＝31.2g）

体重72.5kg・目標119.6gでは 40%＝47.8g で、**不足が大きい日は割合のほうが先に効きます**
（4杯＝41.6gまで）。**50%以上にすると杯数の上限（6杯＝62.4g）が効いて、それ以上は増えません。**
ただし**標準日は1の「不足量」が先に効いて3杯**です（v.144 以降、候補が栄養バランスのために
入るので不足そのものが小さくなりました）。下の表は不足が大きい日の値です。
杯数は g を丸めて決めるので、割合で決まる g に `TOLERANCE`（3g）を足してから1杯あたりのgで割ります。

| 上限% | 賄う量 | 杯数（目標119.6g・不足が大きい日） |
|---|---|---|
| 10% | 12.0 g | 2杯（筋トレをした日の最低杯数で下支え） |
| 20% | 23.9 g | 2杯 |
| 30% | 35.9 g | 3杯 |
| 40%（初期値） | 47.8 g | 4杯 |
| 50%以上 | 59.8 g〜 | 6杯（杯数の上限で頭打ち） |

（表は②の運動を入れ、③の食事を0にして「不足が最大」にした状態で測った値です。）

「① 基本設定」の入力欄の下と、④で早見表を出せないときの案内文に、
いま効いているのが割合なのか杯数の上限なのかを書き分けています。
すでに6杯に達している日は「%を上げても杯数は増えません」と出ます。

### 7. 時間帯別スケジュール

目標からプロテインと間食を引いた残りを各食事に割り振って1食あたりのgを出し、
③ で入力した食品を各食事に自動で割り当てます。
以前は 朝30%/昼35%/夕35% の割合で分け、1食40gで頭打ちにしていましたが、
たんぱく質は割合ではなく**gで見る**ほうが実態に合うためです。

#### 1食の目安は単純な等分ではありません（v.154）

外食の枠は固定メニューで決まっていて、目安に届かないことがあります。
平日の朝食（すき家 まぜのっけ朝食 17.1g）は等分した29.5gに12.4g足りず、
**その差が行き場を失って自宅の食事の片方へ丸ごと寄って**いました。

| 枠 | 目安の決め方 |
|---|---|
| 自宅の食材を置けない枠（外食のメニューだけで決まる枠） | その枠のメニューのたんぱく質。ただし等分した値が上限 |
| 残りの枠（自宅の食材を置ける枠） | 上で余った分を等分 |

**「その枠のメニュー」は `slotsOf` で引きます**（v.156で直しました）。
`slot` の指定だけを見ていると、**店の無料ご飯が数えられません**（その日の定食の枠に
付くので `slot` を持っていない）。木曜に無料ご飯が入ると、朝食の目安が24gのままなのに
実際は29.6gになっていました。

72.5kg・目標119.6g・プロテイン31.2gの平日なら、残り88.4gのうち
朝食が**約17g**、昼食と夕食が**約36gずつ**になります。合計は変わりません。
プロテインの行は、**運動のあとの1回目**と、「プロテインを1日2回まで摂る」（初期値オン）がオンの日の
**夕方の2回目**（夕食の3時間後）の2つです。就寝前だけを狙った行は作りません。
「間食」の行は、昼食が無い2食の設定の日にだけ出ます。

#### ご飯はたんぱく質の少ない枠から配る

ご飯（`spread:true`）は、その日自宅で食べる食事のうち、**たんぱく質の少ない枠から順に**
1杯ずつ配ります（v.154）。1食に置ける杯数は `slotLimit`＝**2杯（1合）**までです。合計は変わりません。

| その日 | ご飯4杯の配分 |
|---|---|
| 朝食が外食・夕食が自宅（3食・日月火水金土） | **昼2・夕2**（1食2杯が上限なので、たんぱく質の少ない昼から埋めても2杯で止まる） |
| 朝食も自宅（3食） | たんぱく質の少ない枠から順に入る |

**v.157までは `slotLimit` が4杯で、この日は「昼4・夕0」でした**
（夕食はサバ缶31.7gだけで1食の目安をほぼ埋めるため、ご飯が全部昼に寄っていた）。
1食2合は食べられる量ではないので、v.158 で2杯に戻しています。

**以前は自宅の食事へ均等に配っていました**（1食1杯ずつ）。
しかし夕食はサバ缶だけで1食の目安をほぼ埋めるので、そこへ均等にご飯を足すと
たんぱく質が夕食に寄ります。さらにその前は昼と夕で半分ずつに分けていたため、
朝食も自宅の日に**朝だけ0杯**にもなっていました。

#### 配分の順番は「枠を選べないもの → 大きい順」

各食品は1単位ずつに分解して、**いちばん不足している枠**へ入れていきます（貪欲法）。
このやり方は**置く順番で結果が変わります。大きい塊を後に回すと必ず行き過ぎます。**
そこで並べ替えてから置きます（v.154）。

1. **枠を選べないもの**（サバ缶＝夕食固定、外食メニュー、割り当て済みのご飯）
2. 残りを**たんぱく質の多い順**

以前は `FOODS` に書いた順でした。サバ缶（31.7g）はアーモンドやヨーグルトより後ろにあるため、
小さい品目で埋めた夕食へ最後に31.7gが乗っていました。

#### 実測（体重72.5kg・基本係数1.65・筋トレ8種目27セット・3食・平日）

| | v.153まで | v.156 | v.158 | **v.159** |
|---|---|---|---|---|
| 朝食（すき家 まぜのっけ朝食） | 17.1 g | 17.1 g | 17.1 g | 17.1 g |
| 昼食 | 16.7 g | 34.4 g | 20.5 g | **24.6 g** |
| 夕食 | 54.2 g | 34.4 g | 48.3 g | **43.7 g** |
| プロテイン（運動のあと3杯） | 31.2 g | 31.2 g | 31.2 g | 31.2 g |
| **合計** | **122.1 g** | **119.1 g** | **119.1 g** | **118.6 g** |

**v.159 で 1食の目安（体重×0.3〜0.6g＝21.8〜43.5g）にほぼ収まりました。**
ヨーグルトを `even` から外して balancer に戻したためです（上記）。

**「自宅の食材を量で均等に分ける」ことと「たんぱく質を均す」ことは、完全には両立しません。**
**サバ缶1缶31.7gが夕食に固定されている**ので、ほかを量で等分すると、
その31.7gがまるごと夕食に上乗せされるためです。

v.158 でいったん 17.1/20.5/48.3 まで悪化しましたが、
**v.159 でヨーグルトを `even` から外して 17.1/24.6/43.7 に戻しました。**
「たんぱく質を均すのは、1回に摂取する量が目安の中に収まればよい」という利用者の判断に沿っています。

**v.154 のこの変更では、③の品目・数量と1日の合計は動かしていません**
（当時はどちらも 122.1 g でした）。⑤の置き場所だけが変わります。
1食の目安は体重×0.4g ＝ 29gなので、v.153の夕食54.2gは体重×0.75gでした。
合計が119.1gに下がっているのは、**v.156 で品目が増えて③の組み合わせが変わった**ためです。

木曜は朝食（吉野家 ハムエッグ納豆定食）も夕食（なか卯 親子丼）も外食のメニューで決まるため、
**自宅の食材は昼食にしか置けません。この日だけは均せません**（実測 朝29.6 / 昼14.7 / 夕30.0）。

#### サラダ一式は同じ食事にそろえる

ミックスサラダ・ノンオイルドレッシング・オリーブオイルは一緒に食べるものなので、
配分したあとに**ドレッシング類をサラダのある食事へ寄せます**。
置き先は1か所にまとめ（1つのサラダにかけるため分けない）、
オリーブオイルは昼、ノンオイルドレッシングは夕を優先します。

朝食も自宅の日に、サラダが昼・夕、ドレッシングと油が朝、と離れてしまうのを防ぐためです。

いまの型はミックスサラダが自動計算の上限の**3皿**まで入りますが、置き先は1か所なので
**サラダ・ノンオイルドレッシング・オリーブオイルは同じ食事にまとまります**
（自宅の夕食の日は夕食、夕食が外食の木曜は昼食）。

#### 1食の中の並び順と、組み合わせの一言

⑤の1食の中は `SCHED_ORDER` の順に並べます（栄養計算には影響しません）。
**ミックスサラダ → ノンオイルドレッシング → オリーブオイル**を隣どうしに置き、
そのあとトマトジュース → 乳製品 → 主菜、最後にご飯・バナナ、という順です。
サラダとドレッシングの間に他の品目が挟まると、別々に食べるように見えてしまうためです。

また、一緒に摂ると効きがよくなる組み合わせが同じ時間帯に入っていたら、その行に一言そえます（`PAIRS`）。

| 組み合わせ | 理由 |
|---|---|
| トマトジュース ＋ オリーブオイル／無脂肪ヨーグルト | リコピンは脂溶性なので、油や乳脂肪と一緒だと吸収が上がる |
| 無脂肪ヨーグルト ＋ サバ缶／ツナ缶 | カルシウムは魚のビタミンDと一緒だと骨に届きやすい |

配分そのものは変えていません。いまの型（自宅の夕食の日）では、サラダ一式とサバ缶が夕食に、
トマトジュースとヨーグルトが昼食と夕食に分かれるため、**結果としてどちらの組み合わせも成立します**
（昼食はヨーグルトの乳脂肪がトマトジュースの相手になります）。
一言は、それが偶然ではなく意図した並びであることを示すために出しています。

**1つの時間帯に2つ出る日もあります**（トマトジュース・ヨーグルト・魚が同じ食事に入る日）。
一言は `display:block` の行なので、**改行タグを付けるのは1つ目の前だけ**です。
2つ目にも付けると、あいだに空行が1行できます（v.140で修正）。

#### 時間帯の見出しに出る「時刻・○時間後」

**その日の1食目の時刻**（既定は朝食 7:00。朝食を抜く設定の日は昼食）を起点に、
各食事の**実時刻**と直前の行からの間隔を見出しに表示します。
抜く食事の行は「昼食（抜く）」のように残り、時刻は表示しません。

| 食事 | 基本の間隔 |
|---|---|
| 朝食 | 起点（「○時間後」は付きません） |
| 昼食 | 3時間後 |
| 夕食 | 「夕食の時刻」を入れればその時刻。空欄なら4時間後（昼食を抜く型では8時間後） |

1食目の時刻を空欄にした日は、**時刻の入っている後ろの食事から基本の間隔だけさかのぼって**
起点を決めます（朝食を空欄・昼食12:00なら、朝食は9:00と表示）。
どの食事にも時刻が無ければ「○時間後」だけの表示になります。

**プロテインの1回目には時刻を出しません**（運動が日に何回かあるため）。

#### 夕食の時刻と「間食」

「② 今日の運動・食事の時刻」の **夕食の時刻**（初期値は**空欄**）を入れると、夕食をその時刻に置きます。
空欄なら基本の間隔（昼食を抜く型なら朝食の8時間後）で自動計算します。

iOS Safari の時刻ピッカーには「クリア」がなく、時刻欄を空欄に戻せません。
そのため注記の下に **「自動計算にする」ボタン**（`#clearDinner`）を置いています。
押すと欄が空欄になり自動計算へ切り替わります。ボタンは時刻が入っているときだけ表示します。
空欄の状態は保存され、設定リンク（#s=）でも他の端末へ運べます。

**納豆・卵・トマトジュースは外食に持ち込めない**ため、これらは外食の朝食・夕食には配分しません。
**昼食が無い2食の設定のときだけ「間食」の行にまとめます**（`home` 指定・`slots:['s']`）。
3食の日は昼食が必ず自宅なので、間食の行は出ません（「自宅の食材をどの枠に置くか」を参照）。
間食を置く時刻は**いちばん間隔が空いている食事どうしの中間**です。食後に高まった筋タンパク合成は3時間ほどで元に戻るため、
朝食と夕食の間の空白をこの間食が埋める形になります。

間食の分は**食事の目安量から差し引いて**から朝・夕へ配分するので、
朝食・夕食の「約○g」は外食メニューで摂る分だけを指します。

朝食7:00・昼食と夕食は空欄（初期値）とした**木曜（外食の日）**の例:

| 時刻 | 行 | 目安量 | 内容 |
|---|---|---|---|
| — | **運動のあとのプロテイン（1回目）** | **3杯（31.2g）** | ＋バナナ2本 |
| 7:00 | 朝食 | **約26 g** | 吉野家 ハムエッグ納豆定食（24.1g）＋吉野家の無料ご飯1杯（5.5g） |
| 10:00 | 昼食（3時間後） | **約26 g** | ミックスサラダ1皿＋オリーブオイル5さじ＋トマトジュース2杯＋アーモンド10粒＋ご飯1杯＋シリアル1食（14.7g） |
| 14:00 | 夕食（4時間後） | **約26 g** | なか卯 親子丼（30g） |
| **17:00** | **2回目のプロテイン（夕食の3時間後）** | **1杯（10.4g）** | ＋バナナ1本 |

**木曜は自宅の食事が昼食しかないので、`even` の分割は効きません。**

朝食と夕食は外食のメニューで決まるので、**その実際の量（29.6g・30g）がそのまま目安**になり、
余った分が昼食に回ります（v.154）。この日は粉が4杯（41.6g）入るため食事側に残るのが
少なく、3つの枠の目安が約26gで並んでいます。

**この日は粉が3杯に収まらないので「2回目のプロテイン」の行が出ます**
（1回の上限が3杯なので、それを超える日だけ2回目が出ます）。

昼食・夕食の時刻が空欄なので、基本の間隔（昼食＝朝食の3時間後／夕食＝昼食の4時間後）で並んでいます。
遅くしたい日は②の欄に時刻を直接入れてください。

**1回目のプロテインに時刻が無いのは意図したものです。**その日の運動のうちどれか1回のあとに摂ります。

3食なので「間食」の行は出ません。夕食が外食のこの日は、自宅の食材がすべて昼食に入ります。

**就寝前の注意は食品の行だけに出します。**間食が20:00以降になる場合は
「⚠ この時刻は就寝前にかかります」と警告しますが、**プロテインの行には警告を出しません**。
ホエイは吸収が速く脂質も少ない（1食2.0g）ため食事のような負担にならず、
就寝前のたんぱく質は睡眠中の修復に使われるからです。代わりに次の補足を添えます。

> 就寝前になりますが、ホエイは吸収が速く脂質も少ないので食事のような負担にはなりません。
> 睡眠中の修復に使われるため、この時刻でも問題ありません。
> 気になる場合は夕食の時刻を早めてください（この行も連動して早まります）。

なお2回目のプロテインを夕食にまとめることは勧めません。夕食（丼もの25〜30g）に粉の1回分を足すと
1回50g超になり、1食の目安（体重×0.4g ＝ 72.5kgで29g）を大きく超えるためです。

**血糖値対策は「食前の難消化性デキストリン」に置き換えています。**自宅の野菜を持ち込めないため、
⑤の朝食・昼食・夕食の各行に「食事の前に難消化性デキストリンを。糖の吸収が穏やかになり、
丼もののご飯による血糖値の急上昇を抑えられます」と表示します。あわせて丼・定食のある食事には
「ご飯は最後に回す。みそ汁の具・卵・肉から先に食べるだけでも血糖値の急上昇は抑えられます」と出します。

#### 朝食メニューの注文期限（11:00）

牛丼チェーンの朝食メニューは11:00までです。その日の朝食枠に朝食メニューが入っている場合、
朝食の時刻が11:00を過ぎると⑤の朝食行に警告を出します。

> ⚠ 11:30 では朝食メニューを注文できません（11:00まで）。
> 「② 今日の運動・食事の時刻」の**朝食の時刻を 11:00 までに早めて**ください。
> 間に合わない日は、朝食を自宅の食材に替えるか、この枠を昼食に回してください。

**この⚠は「くわしい説明を表示する」がオフでも出します。**外食の朝食は週6日あるので、
簡潔表示のときに隠れてしまうと意味がないためです（`breakfastWarn`）。
間に合っている日の「いまの設定では 07:00 なので間に合います」という確認だけは、
くわしい説明のときに出します（`breakfastOk`）。
朝食を抜く型（2食「昼食・夕食」）では、どちらも出ません。

#### 回し分の行（廃止しました）

以前は1食が40gを超えると「昼食の回し分」という行を差し込み、超過分を3時間後に回していました。
**この仕組みは廃止しました。**1回に使えるたんぱく質が40gまでという前提が正しくないためです
（詳しくは「1食あたりのたんぱく質は『上限』ではなく目安」を参照）。

いまは**自動で分割せず**、多い食事にはその行の一言で
「体重×0.6g を超えているので、分散できるなら他の時間帯に回すとより効率よく使えます」と添えるだけです。
コード上は `overBin()` が常に false を返すようにしてあり、回し分の行は出ません。

月曜の例（2食「朝食・夕食」・朝食7:00・夕食は空欄・「プロテインを1日2回まで摂る」オン）:

| 時刻 | 行 | 目安量 | 内容 |
|---|---|---|---|
| — | **運動のあとのプロテイン（1回目）** | **2杯（20.8g）** | ＋バナナ3本 |
| 7:00 | 朝食 | **約17 g** | すき家 まぜのっけ朝食（17.1g） |
| **11:00** | **間食（自宅）** | **約38.8 g** | トマトジュース2杯＋無脂肪ヨーグルト3杯＋アーモンド10粒＋全粒パン2枚＋シリアル2食（38.8g） |
| — | 昼食（抜く） | — | 「上の間食がこの時間帯を埋めます」 |
| 15:00 | 夕食（8時間後） | **約43 g** | ミックスサラダ2皿＋ノンオイルドレッシング1ふり＋オリーブオイル5さじ＋サバ缶1缶＋ご飯2杯（42.6g） |

朝食は外食のメニューなので**17gがそのまま目安**になり、残りが夕食に回ります。
昼食を抜く型では自宅の食材を置ける枠が夕食しかないため、**夕食が厚くなります**（v.154）。

**この日は「2食の日は6杯に固定」が働きません。**候補を除いた不足が固定の線（6杯＝62.4g）に
届かないためです。Bproは1杯が大きく、しかも v.144 以降は候補が栄養バランスのために入るので、
この固定が効く場面はほとんどありません。

昼食を抜く設定では朝食から夕食までの基本の間隔を **8時間** にしています（3食のときは4時間）。
この例は夕食の時刻が空欄なので、その8時間後の15:00に並びます。

- iOS Safari 向けに、フォーム部品の自前描画（チェックボックス・セレクト）、
  フォーカス時の自動ズーム防止（入力欄 16px 固定）、数値キーボードの `inputmode` 指定、

### アイコン

| ファイル | サイズ | 用途 | 中身 |
|---|---|---|---|
| （`index.html` に `data:` で埋め込み） | 32×32 | ブラウザのタブ | 四隅が透明のPNG |
| `favicon-192.png` | 192×192 | 高解像度のタブ・Android | 四隅が透明のPNG |
| `apple-touch-icon.png` | 180×180 | iOSのホーム画面（iPhone 15 Proは@3xで180px） | **不透明**の正方形 |

タブ用の32pxは `data:` URI で **HTMLの中に埋め込んで**います。この1枚を持ち出しても
（`file://` で開いても）アイコンが出るようにするためです。
iOSのホーム画面は `data:` URI を読まないので、`apple-touch-icon` だけは実ファイルを置いています。

四隅の余白は、角丸の半径を決め打ちにせず**画像の各行を端から走査して**透明にしています
（半径を数値で決めると、白が残るか絵の縁が欠けます）。
ただし **iOSは透明部分を黒く塗り、そのうえで自分で角を丸める**ため、
`apple-touch-icon.png` だけは角まで背景色（#0371E0）で塗った不透明の正方形にしています。

`<meta name="apple-mobile-web-app-title" content="Protein Sync">` で、
ホーム画面に並ぶ名前を短くしています（指定しないと `<title>` の全文が使われます）。

アイコンを差し替えたときは、iOSがホーム画面のアイコンをキャッシュするため、
**いったん削除してから追加し直す**必要があります。

### 端末ごとに結果が違うとき

計算式は端末に依存しないため、結果が違う場合は**入力か表示中のバージョンのどちらかが違って**います。
「④ 計算結果」の根拠欄の先頭に、体重・食事回数・基本係数・プロテイン上限・バージョンを表示しているので、
2台の画面を見比べてください。

杯数は初期設定では**空欄（自動）**です。その日の不足量から決まるため、
境界の近くではわずかな入力差でも杯数が変わります。
毎日同じ杯数にしたい場合は「プロテインの杯数を指定」に数を入れて固定してください。

- 起動時に `localStorage` へ書き込めるか確かめ、**できない端末には画面の先頭に警告**を出します
  （プライベートブラウズや、サイトデータの保存を禁止した設定のとき）。
  これまでは例外を握りつぶしていたため、「入力したのに開き直すと消える」ように見えていました。
- 入力内容は `localStorage`（キー `savas-calc-v3`）に保存されます。
  保存領域は**オリジン × ブラウザ × 端末**ごとに独立しており、自動同期は行いません。
  設定を別の端末へ移すには、「① 基本設定」の **「設定リンクをコピー」** を使います
  （URL の `#s=` に画面の入力をすべて埋め込むため、開いた端末にも保存されます）。
  メモに日本語が入るため、`#s=` は UTF-8 に変換してから Base64 にしています
  （`btoa` は Latin1 しか扱えず、日本語をそのまま渡すと例外になります）。
  ASCIIだけの古いリンクは変換しても同じ文字列になるので、そのまま読めます。

  リンクは**ボタンを押した時点のスナップショット**です。押したあとに元の端末で値を変えても
  リンク側は変わりません。反映したいときは押し直して新しいリンクを配ります。
  リンクには作成日も入れてあり、**同じ日に開いた場合だけ食事・距離・実施種目まで復元**します。
  日付が変わってから開いたときは設定だけを反映し、食事はその日の型に戻します
  （食事は毎日入力し直す前提のため）。日付を持たない古いリンクも設定のみ反映します。
  Safari のプライベートブラウズでは保存されませんが、計算自体は正常に動作します。

  **一度読んだリンクは、二度と適用しません**（v.161）。
  それまでは `#s=` が付いたURLで開くたびにリンクの内容を反映していたため、
  **`#s=` 付きのURLをブックマークしたり、iOSのホーム画面に追加していると、
  開くたびに設定がリンクの内容へ巻き戻っていました**
  （「体重を入れ直しても、開き直すと元に戻る」という形で表に出ました）。
  いまは読み込んだリンクを保存内容に控えておき（`lk`）、同じものは読みません。
  あわせて、読み込んだあとは**URLからも `#s=` を消します**。
  **ホーム画面のアイコンはURLが固定なので消えません**が、
  そちらは「同じリンクは二度読まない」ほうで止まります。
  別の内容のリンクを渡せば、いままでどおり反映されます。

  フォークするか、`index.html` の初期値を書き換えてください。
